# Ежедневный режим: как это сделано у других

Разобрано 2026-10-27. Код читался у emdash (Apache-2.0, коммит `85dfa91`), crystal (MIT, `1e18e0b`),
vibe-kanban (Apache-2.0, `a019ceb`), dmux (MIT, `8cb3d92`). Superset (ELv2) — только docs.paradev.com, код не
открывался. Проверено на настоящем Claude Code 2.1.311 (см. «Проверено руками»). Ниже «emdash `x.ts`» — путь в
их репозитории.

## D1. Воркспейс = ветка + worktree

|                | Как сделано                                                                                                                                                                                                                                                                                                                                                                       |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Superset       | ⌘N → имя → kebab-ветка от main (или существующая ветка / PR). Worktree в `<root>/<project>/<branch>`. `.superset/config.json`: `setup` / `teardown` / `run`, env `SUPERSET_ROOT_PATH`, `SUPERSET_WORKSPACE_PATH`; `.env` копируют сами: `cp "$SUPERSET_ROOT_PATH/.env" .env`. Удаление предупреждает о грязном и незапушенном                                                     |
| emdash         | `workspace-registry/node/create-worktree.ts`: inspect → resolve base (если `origin/x` нет локально — fetch только этой ветки) → `worktree add --no-track -b` → проверка по `worktree list --porcelain`; откат только того, что создала эта попытка. Setup в pty через `$SHELL -lc`. Открыть в: таблица приложений, `command -v code && code . \|\| open -a …` (`open-in-apps.ts`) |
| crystal / dmux | crystal: setup построчно через `exec`, вывод после каждой строки; IDE — свободная команда проекта. dmux: хук `worktree_created` с env `DMUX_ROOT`, `DMUX_WORKTREE_PATH`, вывод построчно в UI, ненулевой код — ошибка                                                                                                                                                             |

**Берём.** Наш `createWorktree`/`removeWorktree` из PR #6 + из emdash (Apache-2.0, с атрибуцией): fetch одной
ветки базы и `--no-track` (`create-worktree.ts`), повтор при `.lock` (`git-schedule.ts`, ~20 строк),
предупреждение перед удалением: `status --porcelain=v1 --untracked-files=all` + `rev-list --count <base>..HEAD`.
Setup — `$SHELL -lc '<setupCommand>'` в worktree, вывод построчно в UI (идея dmux), env `STUDIO_ROOT_PATH`,
`STUDIO_WORKSPACE_PATH`, `STUDIO_BRANCH`. «Открыть в»: короткая таблица (Finder — `shell.openPath`; `code`,
`cursor`, `idea`; Terminal, iTerm, Ghostty — `open -a`) + своя команда; `execFile`, без строки shell.

**Не берём.** Детектор установленных приложений через JXA, копирование `.env` по glob с клонированием APFS
(хватит строки в `setupCommand`), teardown и run-скрипты, воркспейс из существующей ветки или PR.

## D2. Встроенный терминал с агентом

|             | Как сделано                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Superset    | Вкладки и сплиты в воркспейсе; процессы и scrollback переживают перезапуск (отдельный демон); ⌘-клик по `src/x.ts:240`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| emdash      | `node-pty@1.1.0` без пересборки: это N-API, готовые бинарники для darwin-arm64/x64 в пакете. Единственная правка — `chmod 755` на `prebuilds/darwin-*/spawn-helper` (иначе `posix_spawnp failed`), `asarUnpack` для упаковки. Env через один `terminal-env.ts`: `TERM=xterm-256color`, `COLORTERM=truecolor`, shell `-il`. Буфер вывода в main — 1 МБ кусками, при переподключении `reset()` + снимок + поток (`wire/src/live/log/source.ts`). Kill: SIGTERM группе процессов, через 2 с SIGKILL. xterm 6 без webgl: canvas/webgl мерцают при resize. Resize — debounce по переднему и заднему краю, иначе Claude рисует в старом размере. Shift+Enter → `\x0A` |
| crystal     | `@homebridge/node-pty-prebuilt-multiarch` + `electron-builder install-app-deps`; буфер — строка 500K (режет escape-последовательности); снимок и подписка разными вызовами — вывод между ними теряется                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| vibe-kanban | Rust `portable_pty`; буфера для переподключения нет, процесс умирает по SIGHUP                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |

**Берём.** `node-pty@1.1.0` (MIT) + postinstall с `chmod` (идея emdash), в `allowBuilds`. Под Electron 45
собирать нечего: N-API. На Linux бинарников нет — `node-gyp` из исходников. Из emdash (Apache-2.0): env,
kill группы, буфер с вытеснением кусков, debounce resize, клавиши (Shift+Enter, Cmd+←/→, копирование).
Снимок буфера и подписка — одним синхронным шагом в main. `@xterm/xterm` 6 + `addon-fit`, `addon-search`.
Терминал не размонтируется при переключении воркспейса, а прячется (как в emdash).

**Не берём.** Демон, переживающий перезапуск (SPEC §3: не в v0.1; рестарт закрывает D4 через `--resume`),
tmux, отдельный рабочий процесс для pty, сплиты.

## D3. Статусы и уведомления

|                    | Как сделано                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Superset           | Свои хуки и обёртки в конфиг каждого агента (`~/.superset/bin`), работают только при их env. Статусы: работает / закончил / ждёт ввода; звук; бейдж на Dock                                                                                                                                                                                                                                                                                           |
| emdash             | Хуки `UserPromptSubmit`→working, `Stop`→completed, `Notification`→awaiting-input — пишет их в **глобальный** `~/.claude/settings.json`. Команда хука — `curl` с токеном через `-K /dev/fd/3`, чтобы он не попал в argv. Сервер `127.0.0.1:0`, `POST /hook`, 403 без токена (`hook-server.ts`, 95 строк). Notification по тексту: `/permission\|approval/i` → разрешение, иначе idle. ОС-уведомление только если окно не в фокусе; клик → фокус задачи |
| dmux / vibe-kanban | dmux: Stop-хук в `.claude/settings.local.json` worktree (попадает в git) + разбор вывода tmux и LLM-классификатор. vibe-kanban: `osascript display notification` + звук                                                                                                                                                                                                                                                                               |

**Проверено руками.** В Claude Code 2.1 есть хук `type: "http"`: POST JSON на URL, заголовки из env только из
`allowedEnvVars`. `claude --settings <файл>` с таким хуком доходит до локального сервера, токен подставляется
из env, `session_id` в теле совпадает с `--session-id`. У Notification есть поле `notification_type`
(`permission_prompt`, `idle_prompt`, `elicitation_dialog`), появилось событие `PermissionRequest`.
`SessionStart` с http-хуком не пришёл.

**Берём.** Сервер по образцу `hook-server.ts` emdash (Apache-2.0): `127.0.0.1:0`, токен на воркспейс
(`STUDIO_HOOK_TOKEN` в env pty, токен → воркспейс, отдельный заголовок не нужен), лимит тела. Файл
`~/.studio/claude-hooks.json` пишется при старте с текущим портом. curl не нужен. Статусы:
`UserPromptSubmit`, `PostToolUse` → working; `PermissionRequest`, Notification `permission_prompt` /
`elicitation_dialog` → needs_input; `Stop` → idle; выход процесса → exited. Из emdash же: не менять статус на
тот же, ОС-уведомление только когда окно не в фокусе или воркспейс не открыт, клик фокусирует воркспейс.
Счётчик — `app.setBadgeCount` (ни у кого нет, своё).

**Не берём.** Классификацию по тексту (есть `notification_type`), запись хуков в любой конфиг агента,
`SubagentStop` (ложный idle), разбор вывода, звук.

## D4. Изменения → коммит → PR, перезапуск

|             | Как сделано                                                                                                                                                                                                                                                                                    |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Superset    | Секции «против базы / коммиты / staged / unstaged», выбор файлов, коммит, push, pull, Create PR; агент после сбоя поднимается `claude --resume <id>`, при неудаче «Failed to resume» + Retry                                                                                                   |
| crystal     | `git add -A` + `commit -m`, без частичного staging; `fs.watch` recursive только активного воркспейса, debounce 1.5 с, обновление по фокусу окна; push без `-u` (новая ветка падает)                                                                                                            |
| vibe-kanban | Diff как у нас (временный индекс), но в индекс добавляются только пути из `status --porcelain` — быстрее на больших репо; `-M`; исключён `node_modules`. PR: `gh pr create --head --base --title --body-file`, URL из stdout, код 4 / «gh auth login» → «не залогинен»                         |
| emdash      | Первый push `--set-upstream origin refs/heads/X:refs/heads/X`. Resume: `--session-id` на старте, `--resume <id>` потом; id обновляется из хуков (меняется после `/clear` и `/resume` в TUI); если resume умер за 3 с — свежий старт. Окно «доверяете папке?» глушат записью в `~/.claude.json` |

**Проверено руками.** Повторный `--session-id` с тем же id — `Session ID … is already in use`. `--resume`
несуществующей сессии — `No conversation found`, выход за ~1 с. `--resume` из другой папки сработал.

**Берём.** Наш `diffFromMergeBase` + из vibe-kanban (переписать): staging только путей из `status`, исключить
`node_modules`. Текстовый diff — разбить `patch` по `diff --git`, раскрасить строки, без зависимостей. Коммит
как в crystal (MIT): `add -A` + `commit -m` массивом аргументов, ошибки хуков из stderr. Push: первый раз
`--set-upstream`, `GIT_TERMINAL_PROMPT=0`, отказ, если ветка = основная. PR как в vibe-kanban, без `gh` —
показать команды и ссылку compare. Обновление как в crystal. Resume как в emdash: последний `session_id` из
хуков в SQLite; после рестарта всегда `--resume`; выход за ~3 с → свежий старт с новым uuid.

**Не берём.** Monaco, частичный staging, Octokit, запись в `~/.claude.json`. Окно доверия Claude показывает
один раз на новую папку — нажать Enter.

## D5. Сбор болей

Ни у кого нет. Своё: строка → `~/.studio/pains.md` (`- 2026-10-27 14:03 · проект · воркспейс · текст`).

## Предлагаю изменить

1. **D3: без классификации по тексту.** `notification_type` и событие `PermissionRequest` вместо регулярки
   emdash; нативный http-хук вместо curl. Плюс `PostToolUse` → working: иначе после разрешения статус висит в
   «ждёт» до конца хода (дыра emdash). `idle_prompt` через минуту после `Stop` второго уведомления не даёт.
2. **D2: без webgl, с web-links.** emdash ушёл с canvas/webgl из-за мерцания при resize, а Chromium держит
   ~16 WebGL-контекстов — на 3 воркспейса × 2 вкладки впритык. Вместо webgl — `addon-web-links`, чтобы
   кликалась ссылка на PR и URL из вывода агента.
3. **D1: база — свежая `origin/<основная>`.** Перед созданием fetch одной ветки (как emdash), без сети —
   локальная. Иначе воркспейс стартует от устаревшей локальной `main` — это та же боль, что сейчас в
   worktree Superset.
4. **D1: маленькая форма настроек проекта.** `setupCommand` есть в схеме, но задать его негде (M2 отложил
   экран проекта). В D1 — поля проекта `setupCommand` и `agentCommand` (по умолчанию `claude`) и общие
   «редактор» и «терминал» — блок в экране проекта, не новый экран.
5. **D2 → D3 → D4: id сессии из хуков.** Claude меняет `session_id` после `/clear` и `/resume` внутри TUI,
   поэтому для D4 храним последний id из хука, а не только сгенерированный в D2. Порядок PR тот же.

## Кандидаты по болям (не в основе)

Воркспейс из существующей ветки или PR; ⌘1…9 для воркспейсов и ⌘T для вкладки; teardown и run-скрипт;
копирование `.env` по списку; ⌘-клик по `file:line` → редактор; бейдж PR и CI в списке; архив удалённых
воркспейсов с восстановлением; Monaco и side-by-side; звук уведомления; терминалы, переживающие перезапуск.
