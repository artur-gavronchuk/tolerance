# Решения вне спеки

- 2026-10-27: `.npmrc` с публичным `registry.npmjs.org` в корне — глобальный npm-реестр машины корпоративный и недоступен вне VPN; Studio не должна от него зависеть.
- 2026-10-27: без поля `packageManager` в корневом `package.json` — pnpm 12 по нему проверяет свою версию через глобальный реестр и падает без VPN.
- 2026-10-27: сборка разрешена только для `electron`, `better-sqlite3`, `esbuild` (`allowBuilds` в `pnpm-workspace.yaml`, синтаксис pnpm 12).
- 2026-10-27: актуальные мажоры на старте: Electron 45, electron-vite 6, Vite 8, TypeScript 7, Biome 2, vitest 5.
- 2026-10-27: preload собирается в CommonJS (`index.cjs`) — иначе не работает `sandbox: true`.
- 2026-10-27: системный шрифт вместо подключаемого — меньше зависимостей, desktop-приложению не нужен веб-шрифт.
- 2026-10-27: tRPC↔IPC — не `electron-trpc`/`trpc-electron` (последние релизы 12.2024 и 01.2025), а тонкий транспорт на публичном API tRPC v11: `fetchRequestHandler` в main, `fetch` через IPC в renderer, подписки через SSE-линк. Делается в шаге 2 M0.
- 2026-10-27: порядок майлстоунов изменён по просьбе пользователя: сразу после каркаса — «открыть проект → понять, из чего он состоит» (часть M1 + Mapper из M3). Чат с агентом, терминал, OpenCode/Codex — позже.
- 2026-10-27: SQLite — встроенный `node:sqlite` (Node 24 в Electron 45) + drizzle `sqlite-proxy` вместо better-sqlite3: та же схема и миграции drizzle-kit, но без нативного модуля и `electron-rebuild`; тесты идут в обычном Node.
- 2026-10-27: агент для карты — временно Claude Code headless (`claude -p --output-format stream-json --json-schema`, только Read/Glob/Grep, `--setting-sources project,local`, `--strict-mcp-config`), а не ACP. Выход нормализуется в те же `NormalizedEvent`, так что переход на ACP не затронет движок и UI. Структурированный ответ приходит в `structured_output`, а не файлом.
- 2026-10-27: `RepoMapJson` расширен полями компонента `tech` и `entities` (таблицы для db, маршруты для backend) — без них не ответить «что в базе, что на фронте». Все поля обязательные (пустые строки/списки), чтобы схема годилась для строгого structured output.
- 2026-10-27: быстрый скан без LLM (`packages/engine/src/scan.ts`): манифесты, compose-файлы, миграции, CI, тесты, языки по размеру файлов. Даёт картину за десятки миллисекунд, пока агент работает; подписи общих находок — ключи i18n.
- 2026-10-27: обновления UI — не tRPC-подписки, а событие `studio:event` из main (что изменилось) + инвалидация запросов TanStack Query. Проще транспорт (только запрос/ответ через IPC); подписки понадобятся для потока терминала.
- 2026-10-27: git через `node:child_process` `execFile`, без `execa` — одной зависимостью меньше, нужного хватает.
- 2026-10-27: PATH берётся из login-shell при старте main: приложение из Dock/Finder иначе не видит `claude` и Homebrew.
- 2026-10-27: `STUDIO_USER_DATA` переопределяет папку данных — e2e-тесты не трогают базу пользователя.
- 2026-10-27: темы по образцу Gerry Themes (JetBrains): Light, Dark, Darcula, Oceanic, Storm, Violet + «Система» (Light/Dark). Палитры из архива gerry-themes v2022.1 (Apache-2.0, атрибуция в `THIRD_PARTY_NOTICES.md`); плоский общий фон сайдбара и контента, кнопки с обводкой акцентом. Цвет окна до загрузки — по системной теме.
- 2026-10-27: по просьбе пользователя первое действие в проекте — создать задачу; агент читает код и даёт оценку (понимание, вердикт go/clarify/reconsider, мнение, сложность S/M/L, что затронет, шаги, риски, вопросы). Это шаг до планирования из SPEC §3.5: из задачи потом вырастет Plan.
- 2026-10-27: задача пользователя в коде — `ChangeRequest` (таблица `change_requests`), а не `Task`: `Task` в спеке — подзадача плана (T1, T2…). Оценка — `Assessment`, новый `Run.kind = 'assess'`, у `runs` появилось `request_id`.
- 2026-10-27: карта больше не запускается сама при добавлении проекта — проект открывается на поле задачи, карта строится по кнопке. Если карта есть, оценщик получает её в промпт; если нет — быстрый скан и структуру папок.
- 2026-10-27: общий цикл «агент → zod-проверка → до 2 повторов» вынесен из Mapper в `executeStructuredRun`; им пользуются Mapper и Assessor (и будут Planner и Verifier).
- 2026-10-27: план создаётся, когда планировщик ответил (статус `awaiting_choice`); статуса `drafting` у плана нет — черновик это сам run `plan`. Так в базе не остаются пустые планы от упавших прогонов.
- 2026-10-27: агент отдаёт оба варианта одним ответом `PlanDraftJson { variants: [2] }`; проверки плана (ключи, зависимости, циклы, критерии, компоненты карты) идут в том же цикле до 2 повторов. В `TaskSpecJson` все поля обязательные (`deny` и `command` бывают пустыми) — для строгого structured output.
- 2026-10-27: дополнительно к SPEC планировщик отклоняет задачу с пустым `scope.allow` и критерий `check: 'command'` без команды — без них не сработают scope-check и проверка командой из §3.5.
- 2026-10-27: утверждение можно снять («Вернуть к выбору»), пока план не исполняется; «Составить заново» создаёт новый план, старый остаётся в базе.
- 2026-10-27: implement-run — тоже Claude Code headless: `--permission-mode dontAsk --permission-prompts none`, разрешены `Read/Glob/Grep/LS`, `Edit(./**)`, `Write(./**)` (правка только внутри worktree, проверено на настоящем `claude`: запись за пределы и Bash отклоняются) и `Bash(<префикс>:*)` из allowlist проекта. Запросы прав в UI (SPEC §3.3) отложены до ACP: сейчас всё, что не разрешено заранее, отклоняется, и отказ виден в ходе работы как событие `permission_denied`.
- 2026-10-27: allowlist команд — поле `projects.allowed_commands` (JSON, по умолчанию пусто); пока без экрана проекта, задаётся только в базе. С пустым allowlist агент не может закоммитить сам — коммитит Studio (`studio: <key> <title>`).
- 2026-10-27: коммит за агента — с `--no-verify` (в worktree нет зависимостей для хуков, ветка своя `studio/*`) и с идентичностью `Studio <studio@localhost>`, только если в git не настроен `user.email`.
- 2026-10-27: пока нет интеграционной ветки, задача ответвляется от основной ветки проекта (`defaultBranch`, если она есть локально, иначе текущей) и diff считается от merge-base с ней. Ветка и путь хранятся в таблице `tasks` (создаётся при первом запуске задачи); статус задачи не хранится отдельно — это статус её последнего implement-run.
- 2026-10-27: slug в пути и ветке — транслит кириллицы в ASCII (`Шаг T1` → `shag-t1`), иначе русские заголовки дают пустой slug.

- 2026-10-27: diff с untracked-файлами считается через временный индекс (`GIT_INDEX_FILE`, `read-tree HEAD`, `add -A`), чтобы не трогать индекс worktree.
