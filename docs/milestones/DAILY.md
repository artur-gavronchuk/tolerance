# Ежедневный режим (замена Superset)

Пункты D1–D5 из `docs/BACKLOG.md`, исследование — `docs/research/daily-driver.md`.

## D1. Воркспейс = ветка + worktree

Сделано:
- `packages/git`: `workspaceLayout` (`~/.studio/worktrees/<project>/ws/<slug>`, ветка `studio/ws/<slug>`),
  `freeWorkspaceSlug`, `freshBase` (fetch одной ветки → `origin/<main>`, иначе локальная), `worktreeChanges`
  (незакоммиченные файлы и коммиты, которых нет на сервере), повтор git при блокировке.
- `packages/db`: таблица `workspaces`, у проекта `editor_command` и `terminal_app`.
- `packages/engine`: `Workspaces` — создание, setup с живым выводом, повтор setup, удаление через guard.
- main: процедуры `workspaces.*`, `projects.updateSettings`; «Открыть в редакторе / терминале / папку».
- UI: воркспейсы выбранного проекта в сайдбаре (ветка, время, setup), экран воркспейса, блок «Воркспейсы» с
  настройками в экране проекта, удаление с предупреждением.

Проверить руками:
- `pnpm dev` → проект → блок «Воркспейсы»: setup, например `pnpm install && cp "$STUDIO_ROOT_PATH/.env" .env`,
  редактор (`cursor`, `idea`…), терминал (`iTerm`, `Ghostty`…) → «Сохранить».
- В сайдбаре под проектом «+» → имя → Enter. Открывается воркспейс: ветка `studio/ws/<slug>`, «от origin/main ·
  sha», вывод setup идёт вживую. Создать ещё 1–2 — список под проектом, свежие сверху.
- «Терминал», «Редактор», «Папка» открывают папку воркспейса. Работать в ней как обычно.
- В основном репозитории: `git status` чистый, `main` не сдвинулась, `git worktree list` показывает воркспейсы.
- Изменить файл в воркспейсе → «Удалить»: список файлов, которые пропадут, и сколько коммитов останется в ветке.
  После удаления папки нет, `git branch --list 'studio/ws/*'` — ветка на месте.
- Выключить сеть и создать воркспейс: предупреждение, ветка от последней известной `origin/main`.
- `pnpm check`, `pnpm test:e2e` — зелёные.

Отложено: встроенный терминал и команда агента (D2), удаление ветки вместе с воркспейсом, teardown,
воркспейс из существующей ветки или PR, копирование `.env` иначе как командой setup.

## D2. Встроенный терминал с агентом

Сделано:
- `node-pty@1.1.0` в main (`apps/desktop/src/main/terminals/`): `PtyHost` — процессы, буфер 1 МБ, пачки вывода с
  номерами, resize, SIGHUP группе процессов с добивкой через 2 с; `Terminals` — вкладки в SQLite (`terminals`),
  команда запуска, окружение.
- Вкладки воркспейса: «claude» (команда агента проекта, `--session-id` от Studio), «shell», «+» для ещё одного
  shell, «Setup» с выводом setup-команды. xterm 6 + fit, search, web-links; без webgl.
- Переключение вкладок и воркспейсов не трогает процессы; перезагрузка окна восстанавливает экран из main.
- Поле «Команда агента» в настройках проекта.

Проверить руками:
- `pnpm dev` → проект → (по желанию) «Команда агента», например `claude --model opus` → новый воркспейс.
- Сразу открыта вкладка «claude»: Claude Code в папке воркспейса (первый раз спросит, доверяете ли папке).
  Поработать, переключиться на «shell», на другой воркспейс и обратно — вывод и процессы на месте.
- Растянуть и сузить окно — TUI Claude перерисовывается под размер. Shift+Enter — новая строка в промпте.
  Cmd+F — поиск, Cmd+K — очистить, Cmd+клик по ссылке открывает браузер.
- «+» — ещё shell, «×» на нём — закрыть. Выйти из claude (`/exit`) → «Запустить claude» начинает новую сессию.
- `sqlite3 "<userData>/studio.db" 'select kind, session_id from terminals'` — у агента записан id сессии.
- `pnpm check`, `pnpm test:e2e` — зелёные.

Отложено: продолжение сессии после перезапуска Studio (`--resume`, D4), статусы агента (D3), подтверждение
закрытия вкладки с работающим процессом, горячие клавиши вкладок, сплиты, тема ANSI-цветов под тему Studio.
