# M1 (переставлен). Проект и его карта

По просьбе пользователя первым делом после каркаса: запускаешь приложение, указываешь локальный проект —
Studio изучает его и раскладывает по частям (фронт, бэкенд, база, инфраструктура, тесты).
Из исходного M1 сюда вошло добавление проекта; из M3 — Mapper и карта. Чат с агентом, терминал,
Codex/OpenCode и ACP переносятся на следующий шаг.

## План

1. `packages/schema` — zod: Project, RepoScan, RepoMapJson (+ `tech`, `entities`), Run, NormalizedEvent.
2. `packages/db` — drizzle-схема (projects, repo_maps, runs, agent_events), первая миграция, node:sqlite.
3. `packages/git` — корень репозитория, ветка, HEAD, список файлов.
4. `packages/engine` — быстрый скан без LLM; Mapper: агент → валидация → до 2 повторов → карта.
5. `packages/agents` — Claude Code headless только на чтение, нормализация событий; фейковый агент для тестов.
6. `packages/prompts` — `map.md`, `validation.md`.
7. main: tRPC поверх IPC, база в userData, PATH из login-shell. UI: список проектов, добавление через выбор
   папки, экран проекта: «Из чего состоит» (скан) и «Карта проекта» (агент, ход работы вживую).

## Итог

Сделано: всё из плана.

Проверить руками:
- `pnpm dev` → «Добавить проект» → выбрать папку с git-репозиторием.
- Сразу появляется блок «Из чего состоит»: языки и находки по категориям (наведение показывает файлы).
- Агент стартует сам: видно, что он читает и ищет; через 1–3 минуты появляется карта — описание продукта и
  компоненты, сгруппированные по видам, с технологиями, таблицами/маршрутами, путями и связями.
- Папка без git → понятная ошибка. «Обновить карту» строит новую. «Убрать из Studio» не трогает файлы.
- `pnpm check` — зелёный. `pnpm test:e2e` — smoke. Настоящий агент:
  `STUDIO_E2E_REPO=/путь/к/репо pnpm --filter @studio/desktop exec playwright test real-agent` (тратит деньги).

Отложено: граф карты (React Flow), выбор модели, кэш карты по коммиту (сейчас «Обновить» всегда запускает
агента), ACP и другие агенты, терминал.
