# M2. Одна задача в worktree

Пункт 2 `docs/BACKLOG.md`: задача утверждённого плана выполняется агентом в своём worktree, по кнопке и по одной.

## План

1. `packages/git`: worktree в `~/.studio/worktrees/<projectSlug>/<planId>/<taskKey>` на ветке
   `studio/<planShort>/<taskKey>-<slug>` от основной ветки; удаление с guard по realpath; коммит за агента;
   diff от merge-base с untracked.
2. `packages/agents`: implement-run Claude Code в worktree: чтение, правка только внутри worktree, Bash только
   из allowlist проекта, без bypass-permissions, тот же поток `NormalizedEvent`.
3. `packages/engine`: `Implementer`, промпт `implement.md`, `beforeSha`/`afterSha` на run.
4. UI: «Выполнить» у задач утверждённого плана, ход работы, итог агента, изменённые файлы, текстовый diff,
   «Удалить worktree».

## Итог

Сделано:
- `packages/git`: `taskWorktreeLayout`, `createWorktree` (переиспользует существующие worktree и ветку),
  `removeWorktree` (только внутри корня после realpath, symlink наружу отклоняется), `commitAll`,
  `diffFromMergeBase` (worktree с untracked через временный индекс, либо ветка, если worktree удалён).
- `packages/agents`: `runClaudeImplement` — `dontAsk` + заранее разрешённые правила, отказы приходят событием
  `permission_denied`.
- `packages/db`: таблица `tasks`, у `runs` — `task_id`, `before_sha`, `after_sha`; у проекта — `allowed_commands`.
- `packages/engine`: `Implementer` — одна задача плана за раз, коммит `studio: <key> <title>`, план → `executing`.
- UI: блок «Выполнение» под утверждённым планом.
