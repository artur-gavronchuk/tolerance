# Как устроена Agent Arena (срез 1)

Практическое объяснение: из чего состоит система, что происходит во время
проверки, где работает агент и что видит владелец. Дизайн и обоснования —
в `docs/superpowers/specs/2026-09-23-agent-connect-and-proof-design.md`,
общая карта продукта — в `docs/superpowers/specs/2026-09-23-platform-roadmap.md`.

## Идея в двух словах

Владелец подключает своего AI-агента. Агент должен доказать, что умеет
работать сам: получает маленький репозиторий с багом, чинит его у владельца
на машине, а платформа проверяет результат скрытыми тестами в изолированной
песочнице. Платформе не важно, что за агент внутри: Claude Code, Codex,
самописный скрипт. Важен только итоговый diff.

## Кто есть кто

| Часть | Где работает | Что делает |
|---|---|---|
| Сайт (кабинет) | `frontend/`, Next.js | регистрация, создание агента и ключей, статус агента, страница проверки |
| API | `backend/cmd/api`, Go | отдаёт данные сайту, раздаёт задачи коннектору, принимает diff |
| Воркер + песочница | горутина внутри API | накатывает diff на чистую копию, гоняет скрытые тесты в Docker |
| Postgres | контейнер | пользователи, агенты, ключи, проверки, очередь задач |
| Коннектор `arena` | **машина владельца** | держит связь с платформой, запускает агента, отправляет diff |
| Агент | **машина владельца** | любая команда, которая правит файлы в папке задачи |

Сайт и коннектор ходят в API по одному адресу, адресу сайта: всё, что
начинается с `/api/`, сайт проксирует в API (на сервере это делает Caddy).
Поэтому в `ARENA_URL` для коннектора указывается адрес **сайта**, не API.

## Путь одной проверки

```
queued → claimed → running_agent → diff_submitted → running_sandbox → passed | failed
   │        │                                              └──────→ infra_error
   └────────┴──────────────── (не дождались) ─────────────────────→ expired
```

1. **Владелец жмёт «Run basic proof».** Открывается экран задачи: условие
   (`TASK.md`), лимиты времени, число видимых и скрытых тестов и правило
   «владелец видит только результат». Кнопка «Start the proof» создаёт
   проверку в статусе `queued`.
2. **Коннектор забирает её.** `arena connect` всё время держит запрос
   «есть задача?» (long-poll до 25 секунд). Как только задача появилась,
   API атомарно переводит её в `claimed`: если запущено два коннектора
   с одним ключом, задачу получит ровно один.
3. **Коннектор готовит рабочую папку у тебя на машине**
   (`$TMPDIR/arena-go-fix-retry-XXXX`): скачивает архив репозитория, сверяет
   sha256, делает `git init` и коммит исходного состояния, кладёт рядом
   `TASK.md`. Статус `running_agent`.
4. **Запускается агент** — команда `agent.command` из
   `~/.arena/config.yaml`, через `sh -c`, **внутри этой папки**. Агент читает
   `TASK.md` и правит файлы прямо на диске. В окружении есть `ARENA_TASK`
   (slug задачи) и `ARENA_PROOF` (id проверки). Весь вывод агента пишется
   в `arena-agent.log` в той же папке. Лимит времени — `agent_timeout_s`
   задачи (у `go-fix-retry` 900 секунд). По таймауту коннектор убивает всю
   группу процессов агента, не только `sh`.
5. **Коннектор собирает результат**: удаляет `TASK.md` и лог из папки,
   делает `git add -A`, выкидывает из индекса файлы больше 1 MiB, снимает
   `git diff --cached --binary` против исходного коммита, чистит хвост лога
   от секретов и отправляет всё на платформу. Статус `diff_submitted`.
   Рабочая папка удаляется. Сбои сети, ошибки сервера (5xx) и 429 при
   скачивании репозитория и отправке результата коннектор повторяет с
   паузой от 2 до 30 секунд, пока платформа ещё ждёт результат
   (`agent_timeout_s + 60` секунд от выдачи задачи).
6. **Воркер проверяет diff**: берёт чистую копию репозитория задачи,
   отказывает, если diff трогает `*_test.go`, применяет diff обычным
   `git apply` (писать за пределы папки нельзя), кладёт поверх скрытые
   тесты и запускает `go test -json` в Docker. Статус `running_sandbox`.
7. **Вердикт** пишется в проверку, и страница проверки показывает результат.

Важно: платформа видит только то, что агент **записал на диск**. Если агент
«решил» задачу только в своём контексте и не сохранил файлы, diff пустой
и проверка падает с `empty_diff`.

## Как решается вердикт

Проверки идут по порядку, первая сработавшая даёт результат:

| Результат | Причина | Что значит |
|---|---|---|
| failed | `diff_too_large` | результат больше 256 KiB; проверка завершается сразу, песочница не запускается |
| failed | `test_file_modified` | diff трогает `*_test.go`; тесты менять нельзя |
| failed | `empty_diff` | агент ничего не поменял |
| failed | `diff_not_applicable` | diff не накатывается на чистую копию |
| failed | `timeout` | тесты не уложились в `sandbox_timeout_s` (120 секунд) |
| failed | `build_failed` | не запустился ни один тест: код не собирается |
| failed | `tests_failed` | упал хотя бы один тест или ненулевой код выхода |
| failed | `hidden_test_missing_or_failed` | упавших нет, но не все скрытые тесты реально запускались (защита от `TestMain` и фильтров `-run`) |
| passed | — | все тесты прошли, и каждый скрытый тест есть в выводе по имени |

Остальные исходы — не провал агента:

- `infra_error` — сломалась платформа: нет Docker-образа, ошибка docker,
  или проверка зависла дольше `3 × sandbox_timeout_s + 20 минут` (причина
  `stuck`). Можно нажать Retry.
- `expired` с `not_claimed` — задачу 5 минут никто не забрал: коннектор
  не запущен.
- `expired` с `agent_timeout` — результат не пришёл за
  `agent_timeout_s + 60` секунд: агент не уложился или коннектор потерял
  связь.

Retry доступен только для `infra_error` и `expired`.

## Где код агента и что уходит на платформу

Агент работает **только у владельца**. Что уходит на платформу:

- diff (до 256 KiB);
- хвост лога агента, до 32 KiB, после чистки: ANSI-коды, JWT, ключи вида
  `sk-…`/`ak_…`/`ghp_…`/`AKIA…`, `Bearer …`, пары `token=`/`password:`,
  PEM-блоки, длинные hex- и base64-строки заменяются на `[redacted]`.
  Сервер повторяет чистку независимо от коннектора;
- длительность работы и код выхода агента;
- в heartbeat — имя хоста и версия коннектора.

Не уходит: ключи модели, промпты, конфиг агента, полный лог, файлы больше
1 MiB. Рабочая папка и полный лог удаляются после прогона.

## Что видит владелец

- **Главная `/app`** — одна карточка «что сейчас» по стадии агента и список
  проверок.
- **Экран задачи `/app/proofs/new`** — перед запуском: условие, лимиты,
  число тестов. Проверка запускается только отсюда.
- **Страница подключения `/app/agent/connect`** — команда скачивания
  коннектора, остальные команды, индикатор онлайна (обновляется раз в 5
  секунд), выпуск и отзыв ключей.
- **Страница проверки `/app/proofs/<id>`** — таймлайн шагов со временем
  каждого шага и длительностью работы агента и тестов, вердикт, таблица
  тестов, diff агента с подсветкой, хвост лога.

Если API недоступен, кабинет показывает ошибку и кнопку «Try again».

Чего не видно: вывода агента в реальном времени (diff приходит только
в конце) и локальной папки. Посмотреть, что агент делает прямо сейчас,
можно на своей машине, пока идёт прогон:

```sh
tail -f $TMPDIR/arena-go-fix-retry-*/arena-agent.log
```

Вмешаться в проверку нельзя, и это сделано специально: проверка доказывает,
что агент справляется без человека. Ручной отправки результата нет.
Ctrl-C в `arena connect` прерывает агента, но результат не уходит, и
проверка через `agent_timeout_s + 60` секунд станет `expired`.

## Стадии агента

Стадия не хранится в базе, она вычисляется каждый раз (`internal/agents/stage.go`):

| Стадия | Когда |
|---|---|
| `registered` | нет активного ключа или коннектор ни разу не выходил на связь |
| `offline` | последний heartbeat старше 2 минут |
| `connected` | коннектор на связи, успешных проверок ещё нет |
| `checking` | есть незавершённая проверка (важнее онлайна: пока проверка идёт, стадия `checking`, даже если коннектор пропал) |
| `operational` | есть хотя бы одна `passed` и коннектор на связи |
| `check_failed` | последняя завершённая проверка `failed`, `passed` ещё не было |

Heartbeat коннектор шлёт раз в 30 секунд.

## Песочница

Контейнер из образа задачи (`arena-proof-go:1`): без сети, 1 GB памяти,
1 CPU, до 256 процессов, все Linux capabilities сброшены,
`no-new-privileges`, `/tmp` в памяти на 512 MB, вывод теста ограничен.
Файлы попадают в контейнер через `docker cp`; поэтому `--read-only` пока
не включён (подробности в комментарии к `Docker.Run` в
`backend/internal/proofs/sandbox/docker.go`). API управляет Docker через
`/var/run/docker.sock` — осознанный компромисс первого среза.

## Ограничения

- один агент на пользователя, до 5 активных API-ключей;
- одна незавершённая проверка на агента;
- 10 проверок в сутки на агента;
- сессия 30 дней; `start`/`callback` OAuth — 20 запросов в минуту на IP,
  dev-вход — 10 в минуту на IP и на e-mail.

## Запустить локально

Весь стек в Docker:

```sh
make up        # сайт на http://localhost:$WEB_PORT (по умолчанию 3000)
make logs
make down
```

Нативно (Postgres из compose, API и сайт на хосте):

```sh
cp -n .env.example .env
docker compose up -d postgres        # или docker-compose
make migrate
make proof-image                     # образ песочницы, если его ещё нет
make connector                       # бинарники коннектора для страницы Connect
make run-api                         # слушает 127.0.0.1:$API_PORT
```

Во втором терминале:

```sh
make run-web                         # сайт на :$WEB_PORT, /api проксируется в API
```

В Superset-воркспейсе порты выбирает `.superset/setup.sh` и пишет их
в `.env` (`WEB_PORT`, `API_PORT`): 3000 и 8080 на машине могут быть заняты
чем-то другим.

Войди через GitHub, Google или (локально) dev-вход на `/login`. Dev-вход —
поле с любым e-mail без пароля, доступен только когда в `.env` стоит
`ARENA_DEV_LOGIN=true` (так по умолчанию в `.env.example`; в продакшне не
ставить). Роль admin получают e-mail из `ARENA_ADMIN_EMAILS` в `.env`.

## Подключить агента

1. На сайте: регистрация → создать агента → скопировать ключ
   (показывается один раз).
2. Скачать коннектор (macOS или Linux; команда с адресом твоего сайта есть
   на странице подключения):

   ```sh
   curl -fsSL "http://localhost:3000/api/v1/connector/download?os=$(uname -s)&arch=$(uname -m)" -o arena
   chmod +x arena && sudo mkdir -p /usr/local/bin && sudo mv arena /usr/local/bin/arena
   ```

   Сервер отдаёт готовые бинарники для darwin и linux на amd64 и arm64: в
   Docker-образе API они собираются при сборке, при нативном запуске —
   командой `make connector`. Без них скачивание отвечает 404
   `connector_unavailable`, и коннектор можно собрать из репозитория:
   `cd backend && go build -o arena ./cmd/arena`.
3. Сохранить ключ — коннектор читает его из stdin и кладёт
   в `~/.arena/key` с правами 0600:

   ```sh
   arena login
   ```
4. Создать конфиг. `ARENA_URL` — адрес **сайта**:

   ```sh
   ARENA_URL=http://localhost:3000 arena init
   ```

   Если `~/.arena/config.yaml` уже есть, `init` откажется — поправь `url`
   в файле руками. Переменная `ARENA_URL` при запуске любой команды
   перекрывает `url` из файла.
5. Указать, как запускать агента, в `~/.arena/config.yaml`:

   ```yaml
   url: http://localhost:3000
   agent:
     command: claude -p "$(cat TASK.md)" --dangerously-skip-permissions
   ```

   Подойдёт любая команда, которая правит файлы в текущей папке:
   `codex exec "$(cat TASK.md)"`, свой скрипт и т. п. Флаг
   `--dangerously-skip-permissions` нужен Claude Code, чтобы он не ждал
   подтверждения на каждую правку: отвечать некому.
6. Выйти на связь и держать окно открытым:

   ```sh
   arena connect
   ```

   Через несколько секунд на странице подключения появится «Online»,
   и на главной станет доступна кнопка «Run basic proof».

`ARENA_HOME` меняет папку `~/.arena`, если нужно несколько конфигов.
`arena status` показывает стадию агента и последнюю проверку. Это не
heartbeat: он не делает агента онлайн.

## Частые проблемы

| Симптом | Причина и что делать |
|---|---|
| `heartbeat: 404 : Not found` | `url` в конфиге указывает не на сайт Arena (например, порт занят другим сервисом). Проверь адрес, открыв его в браузере, и поправь `url` |
| `API key rejected; run arena login…` | ключ отозван или неверный: выпусти новый на странице подключения и сделай `arena login` |
| `expired`, `not_claimed` | коннектор не был запущен, когда нажали «Run» |
| `expired`, `agent_timeout` | агент не уложился в 15 минут или коннектор потерял сеть |
| `failed`, `empty_diff` | агент не записал файлы. Частая причина — агент ждёт подтверждения (для Claude Code нужен `--dangerously-skip-permissions`) |
| `infra_error` | чаще всего нет образа `arena-proof-go:1`: `make proof-image` |
| «Could not load your account» в кабинете | API недоступен или перезапускается; «Try again» повторит запрос |
| `failed`, `diff_too_large` | агент наменял больше 256 KiB (часто — сгенерированные файлы или зависимости в репозитории); проверь, что он правит только нужное |

## Известные недоделки

- Песочница без `--read-only` (см. раздел «Песочница»).
- Коннектор работает только на macOS и Linux: агент запускается через
  `sh -c`.
