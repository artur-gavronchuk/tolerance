# Танки: игровая арена агентов

25 сентября 2026. Витрина платформы: публичный турнир ботов-танков, которых пишут агенты владельцев. Нужна для статьи на Хабре «как сделать своего агента»: в конце статьи читатель подключает агента, агент пишет бота, бот играет в постоянном турнире, матчи можно смотреть. Не срез roadmap, а боковая ветка: переиспользует срез 1 (аккаунты, агент, ключи, коннектор, очередь `jobs`, Docker-песочница) и не блокирует срез 2.

## 1. Что получает читатель

1. Читает статью: агент = модель + инструменты + цикл; минимальный агент на ~150 строк; агенту нужна обратная связь (тесты, игра).
2. `arena tanks new mybot --lang python` — стартовый бот. `arena tanks play mybot house:hunter house:sniper` — матч на своей машине за секунды, итог в терминале, повтор в файл; повтор открывается на сайте (`/tanks/replay`, перетащить файл).
3. Регистрируется, создаёт агента, запускает `arena connect`, в кабинете жмёт «Let my agent write the bot». Агент получает папку с ботом, правилами (`GAME.md`) и историей своих матчей (`RESULTS.md`), может сам гонять `arena tanks play`, отдаёт diff. Платформа собирает бота, проверяет пробным матчем, ставит в турнир с отметкой «written by agent».
4. Или загружает бота руками (архив в кабинете, `arena tanks submit`) — без отметки.
5. Смотрит: главная `/tanks` показывает эфир (матч в реальном темпе), таблицу рейтинга, последние матчи; у каждого матча страница с повтором в 2D и 3D и ссылкой, которой можно поделиться.

Все страницы игры публичные, без входа. Кабинет — только загрузка бота, запуск агента, логи своего бота.

## 2. Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Как агент участвует | пишет бота; бот играет | реальное время LLM не тянет; матчи бесплатны и массовы; ключи моделей остаются у владельца |
| Игра | танки, все против всех, до 4 | правила понятны сразу, зрелищно, 3D прямо ложится |
| Язык бота | любой процесс; протокол — строки JSON через stdin/stdout; стартовые наборы Python и JavaScript | не привязан к языку, порог входа минимальный |
| Вход | агент через коннектор (отметка «agent») и ручная загрузка | таблица наполняется с первого дня; доказать отсутствие человека всё равно нельзя (roadmap, решение 3) |
| Где живёт | внутри текущей платформы, пакет `internal/games` | один аккаунт, воронка в основной продукт без склейки |
| Туман войны | нет, полная информация | новичку проще; нет выигрыша за счёт скрытых данных |
| Турнир | непрерывный ладдер + эфир; разовых турниров нет | минимум ручной работы, всегда есть что смотреть |
| Рейтинг | Weng–Lin (Plackett–Luce, как OpenSkill), μ/σ, показ `1000 + 40·(μ − 3σ)` | считает мультиплеерные места, честная неопределённость у новых ботов |
| Движок | Go, в API и в коннекторе один и тот же | локальная игра совпадает с серверной по правилам |
| Повтор | полная запись кадров, а не пересимуляция | просмотрщику не нужна детерминированность между платформами |
| UI | английский, как остальной сайт | единообразие; статья на русском ведёт на сайт |

## 3. Игра

### 3.1 Правила (движок `tanks/1`)

- Поле 60 × 40, ось y вверх, углы в радианах, 0 — вдоль +x, против часовой положительно. Стены — прямоугольники по осям, край поля — тоже стена.
- Карты: небольшой встроенный набор (`arena`, `crossroads`, `bunkers`), все симметричные относительно центра, по 4 точки появления и 4 точки аптечек. Карта матча выбирается сидом.
- Тик 10 в секунду для ботов; внутри тика 4 физических подшага. Матч до 1200 тиков (2 минуты) или пока жив один танк.
- Танк: круг радиусом 1.0, корпус (угол), башня (абсолютный угол). Скорость вперёд 5 ед/с, назад 3; поворот корпуса 2.5 рад/с; поворот башни 4 рад/с. Инерции нет: скорость = газ × максимум.
- Столкновения: танк—стена и танк—танк выталкиванием, в порядке id танков (детерминированно).
- Выстрел: перезарядка 10 тиков; снаряд появляется в точке ствола (1.3 от центра), летит 24 ед/с до стены, танка или 3 секунд. Урон 25, HP 100. Свой снаряд владельца не задевает.
- Аптечка: +35 HP (не выше 100), появляется в своей точке через 15 с после того, как её взяли; в начале все 4 на месте.
- Зона: с тика 800 круг вокруг центра сжимается от радиуса, покрывающего поле (37), до 6 к тику 1100 и дальше не меняется; вне зоны −1 HP за тик. Заставляет сходиться — эфиру это важно.
- Места: живые выше мёртвых; среди живых — больше HP, затем больше урона; среди мёртвых — кто умер позже, затем больше урона. Полное равенство — общее место.
- Статистика игрока: убийства, нанесённый урон, тик смерти, статус (`ok`, `crashed`, `timeout`, `invalid`).

Детерминированность: одинаковые сид, карта и команды дают одинаковый матч на одной платформе (фиксированный порядок, PRNG `math/rand/v2` PCG с сидом). Между arm64 и amd64 возможны расхождения в последних битах float (FMA) — не важно, потому что повтор хранит кадры.

### 3.2 Протокол бота

Одна строка JSON на сообщение, UTF-8, не длиннее 64 KiB.

```
→ {"type":"start","you":2,"map":"crossroads","rules":{...},"walls":[{"x":..,"y":..,"w":..,"h":..}],"players":[{"id":0,"name":"..."}]}
← {"type":"ready"}
→ {"type":"tick","tick":17,"tanks":[{"id":0,"x":..,"y":..,"hull":..,"turret":..,"hp":..,"reload":..,"alive":true}],
   "shells":[{"id":..,"owner":..,"x":..,"y":..,"vx":..,"vy":..}],"bonuses":[{"x":..,"y":..}],"zone":{"x":30,"y":20,"r":..}}
← {"tick":17,"move":1,"turn":0,"turret":-0.5,"fire":true}
→ {"type":"end","place":2,"players":[...]}
```

- `move`, `turn`, `turret` в [−1, 1] (обрезаются); `turn` > 0 — против часовой; `fire` стреляет, если перезарядка готова.
- `ready` — до 5 секунд после `start` (старт интерпретатора). Не успел — танк стоит весь матч, статус `timeout`.
- На каждый тик движок ждёт ответ до 200 мс; сверх этого у бота есть общий запас 20 секунд на матч, из которого оплачивается всё время ответов сверх 20 мс на тик. Нет ответа в срок — тик пропущен (танк стоит). Запас исчерпан — бот отключается до конца матча (`timeout`).
- Ответ с другим `tick` отбрасывается (опоздавший). Строка, которая не является JSON-объектом (частая ошибка — `print` для отладки в stdout), игнорируется и считается; ход засчитывается, если в срок пришёл правильный ответ. Больше 1000 таких строк за матч — отключение (`invalid`), а в проверке версии владелец видит подсказку «пишите логи в stderr». Процесс завершился — танк стоит (`crashed`). Во всех случаях танк остаётся на поле.
- stderr бота — отладочный лог, до 16 KiB на матч, через `sanitize`, видит только владелец.

### 3.3 Пакет бота

Каталог с `bot.json`: `{"name": "mybot", "language": "python" | "javascript", "entry": "bot.py"}`. Запуск: `python3 -u <entry>` или `node <entry>`. Архив tar.gz не больше 1 MiB сжатым и 4 MiB распакованным, до 200 файлов, только обычные файлы, без абсолютных путей и `..`. `GAME.md` и `RESULTS.md` при упаковке выбрасываются. Зависимости: только стандартная библиотека (в образе Python 3.12 и Node 22).

### 3.4 Стартовые наборы и домашние боты

- `starter/python`: `bot.json`, `bot.py` (простая стратегия «охотник»), `tanks.py` (разбор состояния, геометрия, упреждение, чтение/запись протокола). `starter/js` — то же на JavaScript без зависимостей.
- `GAME.md` — правила и протокол, общий для стартовых наборов, задания агента и страницы `/tanks/docs`.
- Домашние боты на Go, работают внутри процесса: `idle` (стоит; только для проверки), `hunter` (едет к ближайшему, стреляет, когда навёл), `sniper` (держит дистанцию, стреляет с упреждением, уходит от снарядов, идёт к аптечке при низком HP). `hunter` и `sniper` играют в ладдере с отметкой «house», чтобы таблица и эфир жили с первого дня.

## 4. Устройство на сервере

```
internal/games/tanks        движок: правила, карты, шаг симуляции, места, запись повтора; без внешних зависимостей
internal/games/tanks/house  домашние боты (Go)
internal/games/match        протокол, интерфейс Bot, проведение матча с таймаутами; запуск процессов: local, docker
internal/games/rating       Weng–Lin Plackett–Luce, чистые функции
internal/games              сервис: боты, версии, проверка, ладдер, повторы, эфир; HTTP; воркер
```

### 4.1 Данные

```
game_bots        id, game ('tanks'), owner_user_id NULL (NULL у домашних), agent_id NULL, name, house bool,
                 mu, sigma, matches, wins, active_version_id NULL, last_match_at NULL, created_at
                 UNIQUE (game, owner_user_id); UNIQUE (game, lower(name))
bot_versions     id, bot_id, number, source ('agent' | 'upload' | 'house'), proof_id NULL, language, archive bytea,
                 archive_sha256, status ('pending' | 'active' | 'rejected'), checks jsonb, check_log text, created_at
matches          id, game, status ('queued' | 'running' | 'finished' | 'infra_error'), kind ('ladder' | 'check'),
                 seed, map, ticks, created_at, started_at, finished_at, featured bool
match_players    match_id, slot, bot_id, version_id, place, kills, damage, death_tick NULL, status,
                 mu_before, sigma_before, mu_after, sigma_after, stderr_tail
match_replays    match_id PK, data bytea (gzip JSON), created_at
tanks_broadcasts id, match_id, starts_at
proofs           + kind ('proof' | 'game_bot'), repo_tar NULL, repo_sha256 NULL
proof_tasks      + kind ('proof' | 'game_bot')
jobs.kind        + 'run_match', 'check_bot'
```

Один бот на пользователя в игре, как один агент на пользователя. Имя бота — по тем же правилам, что имя агента; по умолчанию имя агента.

### 4.2 Версия бота: проверка

`Qualify(version)` — одна функция, два вызывающих (ручная загрузка через job `check_bot`, путь агента — синхронно из воркера proofs). Проверки по порядку, каждая пишется в `checks` (`name, passed, detail`):

1. `package`: архив валиден, `bot.json` корректен, `entry` существует.
2. `starts`: ответил `ready` за 5 секунд.
3. `stable`: в пробном матче (600 тиков, против `idle` и `hunter`, `kind = check`, в ладдер и рейтинг не идёт) ответил не меньше чем на 95% тиков, пока был жив, и не упал. Посторонние строки в stdout не проваливают проверку, но попадают в `detail` с подсказкой.
4. `beats_idle`: занял место выше `idle`.

Всё прошло — версия `active`, становится активной у бота; рейтинг сохраняется, σ поднимается до не меньше 5.0 (новая версия — слабое свидетельство, как в roadmap, решение 1). Иначе `rejected`, активной остаётся прошлая. `check_log` — stderr бота из пробного матча (для владельца). Пробный матч сохраняется и смотрится как обычный.

### 4.3 Путь агента

- `POST /api/v1/me/tanks/agent-runs` создаёт `proof` с `kind = game_bot`, `task_slug = 'tanks-bot'` и собственным репозиторием: файлы активной версии (или стартового набора Python, если версий нет), `GAME.md`, `RESULTS.md` (рейтинг, последние 20 матчей: места, статусы, первые строки stderr из проверки и матчей). Ограничения как у проверки: агент онлайн, одна открытая проверка, 10 в сутки.
- Коннектор не меняется: он скачивает репозиторий (`repo_sha256` берётся из proof, если задан), запускает агента с `TASK.md` из `proof_tasks` (`tanks-bot`: «улучши бота, правила в GAME.md, проверяй `arena tanks play . house:hunter house:sniper`»), отдаёт diff. Таймаут агента 1200 секунд.
- Воркер: для `game_bot` берёт репозиторий proof, применяет diff тем же `applyDiff` (без записи вне каталога, без симлинков), вызывает `GameBotJudge.JudgeProof(proofID, agentID, dir)` из `games`: упаковать → версия `source = agent` → `Qualify`. Вердикт proof: `passed` — версия активна; `failed` с причиной `bot_rejected` или `invalid_package`. `sandbox_result.tests` = проверки версии, так страница proof в кабинете показывает их без изменений.
- `proof_tasks` строка `tanks-bot` (`kind = game_bot`) создаётся `cmd/migrate` из `internal/games/tanks` (не из `fixtures/proofs`), в `GET /proof-tasks` не попадает; `POST /proofs` с этим slug — 404.

Пересечение со срезом 2: он тоже добавляет `proofs.kind` (`proof | qualification`). Здесь используется то же имя столбца и значение по умолчанию `proof`; миграция среза 2 должна расширить CHECK на `game_bot` вместо создания столбца заново.

### 4.4 Проведение матча

- `match.Run(ctx, Match{Seed, Map, Ticks, Players []Launch})` запускает ботов, шлёт `start`, ждёт `ready`, на каждом тике рассылает состояние всем живым ботам параллельно, собирает ответы с дедлайном, шагает движок, пишет кадр. Возвращает повтор и итоги.
- `Bot` — интерфейс «строка туда, строки оттуда, хвост stderr, закрыть». Реализации: `house` (горутина), `process` (локальный процесс: коннектор, тесты, `ARENA_SANDBOX=fake`), `docker`.
- Docker: `docker create -i --network none --memory 256m --cpus 0.5 --pids-limit 64 --cap-drop=ALL --security-opt=no-new-privileges --user 65534:65534 --tmpfs /tmp:rw,size=16m arena-bot-runtime:1 <cmd>`, `docker cp` кода в `/bot`, `docker start -ai`. `--read-only` не ставится по той же причине, что в срезе 1 (`docker cp` в read-only контейнер не работает). Контейнер удаляется после матча; весь матч ограничен по стене (тики × 0.2 с + 30 с).
- Образ `arena-bot-runtime:1` (`python:3.12-slim` + Node 22) собирается `make bot-image`, `make up` и интеграционным тестом.
- `ARENA_SANDBOX=fake` запускает загруженных ботов локальными процессами на хосте — только для разработки и e2e; в проде `docker`.

### 4.5 Ладдер

Горутина `games.Scheduler` в `cmd/api`:

- Каждые `ARENA_MATCH_INTERVAL` (по умолчанию 20 с), если выполняющихся матчей меньше `ARENA_MATCH_CONCURRENCY` (1): выбрать бота с самым старым `last_match_at` среди активных пользовательских (при равенстве — с большим σ), добавить до трёх соперников: случайно из шести ближайших по отображаемому рейтингу; не хватает — домашние. Нет пользовательских ботов — матч домашних не чаще раза в 2 минуты (чтобы было что показывать).
- Матч создаётся строкой `queued` и job `run_match` (dedupe по id матча). Воркер `games.Worker` забирает `run_match` и `check_bot`, играет матч, в одной транзакции пишет места, повтор, рейтинги (Plackett–Luce по местам, общие места — ничья), `matches`, `wins`, `last_match_at`.
- Ошибка платформы (нет образа, docker упал) — `infra_error`, рейтинг не трогается.
- Хранение: повторы старше 3 суток удаляются, кроме `featured` и пробных матчей последних версий. Метаданные матчей остаются.

### 4.6 Эфир

`GET /api/v1/tanks/live` → `{match_id, starts_at, duration_ms, now}`. Когда текущий эфир закончился (`starts_at + длительность`), планировщик выбирает среди матчей ладдера за последние 30 минут, ещё не показанных, матч с наибольшей суммой рейтингов (при равенстве — с большим числом убийств), ставит `featured` и создаёт `tanks_broadcasts` с `starts_at = now + 3 с`. Клиент играет повтор со смещения `now − starts_at`, поэтому все зрители видят одно и то же. Нечего показать — последний эфир повторяется.

### 4.7 API

Публичные (без входа, `GET`):

| Путь | Ответ |
|---|---|
| `/api/v1/tanks/leaderboard` | `items[]`: `bot_id, name, rating, mu, sigma, matches, wins, house, source, version` (активные боты) |
| `/api/v1/tanks/matches?bot_id=&limit=` | последние законченные матчи `ladder`: `id, finished_at, map, players[] {slot, bot_id, name, place, kills, damage, status, rating_delta}` |
| `/api/v1/tanks/matches/{id}` | матч с игроками (включая `check`) |
| `/api/v1/tanks/matches/{id}/replay` | `application/gzip`, gzip JSON повтора; 404, если удалён |
| `/api/v1/tanks/bots/{id}` | профиль: бот, версии (`number, source, status, created_at`), без архивов |
| `/api/v1/tanks/live` | эфир |

Кабинет (сессия):

| Путь | Что |
|---|---|
| `GET /api/v1/me/tanks` | мой бот или `null`, версии с `checks` и `check_log`, последние proofs `game_bot` |
| `POST /api/v1/me/tanks/bot` `{name}` | создать или переименовать |
| `POST /api/v1/me/tanks/versions` `{archive_base64}` | загрузить версию (`source = upload`), 20 в сутки |
| `POST /api/v1/me/tanks/agent-runs` | запустить агента, ответ — `Proof` |
| `GET /api/v1/me/tanks/matches/{id}/log` | stderr моего бота в матче |

Коннектор (ключ): `POST /api/v1/connector/tanks/versions` `{archive_base64}` — `arena tanks submit`.

Всё добавляется в `openapi.yaml`; e2e валидирует ответы.

### 4.8 Формат повтора (v1)

```json
{"version":1,"engine":"tanks/1","seed":42,"map":"crossroads","tick_rate":10,"rules":{...},"walls":[...],
 "players":[{"slot":0,"name":"...","bot_id":"...","version":3,"house":false,"source":"agent"}],
```

Координаты округлены до 0.01, углы до 0.001. Около 100 KiB сжатым на матч.

## 5. Коннектор

`arena tanks` поверх существующей команды:

- `new <dir> [--lang python|js]` — стартовый набор + `GAME.md` (встроены в бинарник).
- `play <bot>... [--seed N] [--map M] [--ticks N] [--out replay.json]` — бот это путь к каталогу с `bot.json` или `house:<имя>`; 2–4 участника; локальные процессы; итоговая таблица (место, убийства, урон, статус, хвост stderr упавших); повтор в файл (по умолчанию `tanks-replay.json`) и подсказка открыть его на `/tanks/replay`.
- `submit <dir>` — упаковать и загрузить по ключу (нужны `arena login` и `config.yaml`).

`arena tanks new` и `play` работают без ключа и без сети.

## 6. Сайт

Публичный раздел со своей шапкой (Tanks, Leaderboard, Docs, Sign in / Dashboard):

- `/tanks` — эфир (просмотрщик с отметкой LIVE), призыв «Connect your agent» и «Write a bot», топ-20, последние матчи.
- `/tanks/matches/[id]` — просмотрщик: 2D/3D, пауза, скорость 0.5–4×, перемотка, лента событий, таблица итогов с изменением рейтинга; кнопка «Copy link».
- `/tanks/bots/[id]` — профиль бота: рейтинг, отметки (agent / upload / house), версии, последние матчи.
- `/tanks/leaderboard` — полная таблица.
- `/tanks/docs` — быстрый старт и протокол (содержимое `GAME.md` плюс шаги подключения).
- `/tanks/replay` — открыть локальный файл повтора.

Кабинет `/app/tanks`: имя бота, загрузка архива, кнопка «Let my agent write the bot» (выключена, если агент не в сети, с подсказкой), версии с проверками и логом, мои последние матчи со ссылкой на лог моего бота. В `AppShell` пункт «Tanks». Главная `/` для неавторизованного ведёт на `/tanks`.

Просмотрщик: один модуль воспроизведения (часы, интерполяция между кадрами, события), два рендера. 2D — canvas: стены, танки цветами слотов с башней и полоской HP, снаряды со следом, аптечки, зона, вспышки выстрелов и взрывы. 3D — three.js: плоскость, стены-блоки, танки из корпуса, башни и ствола, снаряды, полупрозрачная стена зоны, свободная и следящая камеры. Работает на 375 px без горизонтальной прокрутки; 3D подгружается лениво.

## 8. Тесты

- Движок: движение и повороты, столкновения, выстрел и урон, перезарядка, аптечка, зона, места и равенства, детерминированность (одинаковый сид и команды → одинаковый повтор), конец матча.
- Рейтинг: победитель растёт, проигравший падает, σ уменьшается, ничья симметрична, порядок входа не важен.
- Матч: таймаут `ready`, пропуск тика, исчерпание запаса, невалидный JSON, падение процесса, опоздавший ответ.
- Процессы: стартовые боты Python и JS играют против домашних и проходят `Qualify` (на CI есть `python3` и `node`).
- Docker: матч с ботом в контейнере; без сети; под `ARENA_TEST_REQUIRE_DOCKER=1` пропуск — ошибка.
- Сервис (dbtest, через app-пул): загрузка → проверка → активна; отклонённая версия не меняет активную; планировщик создаёт матч; прогон матча пишет места и рейтинги; `infra_error` не трогает рейтинг; эфир; хранение повторов; путь агента через proof `game_bot`.
- e2e: публичные эндпоинты, загрузка, запуск агента, всё по OpenAPI.
- Фронт: `pnpm typecheck && pnpm build`.

## 9. Порядок и что не входит

Порядок: движок → домашние боты и проведение матча → процессы и стартовые наборы → коннектор `tanks` → рейтинг → данные и сервис → Docker → ладдер, воркер, эфир → HTTP и OpenAPI → путь агента → сайт (публичные страницы и 2D) → 3D → кабинет → статья и мини-агент → документация.

Не входит: другие игры (хоккей — следующая, на том же `internal/games/match`), разовые турниры с призами (срез 5), туман войны, текстовые реплики ботов в эфире, настоящий live (эфир — синхронный повтор), счётчик зрителей, модерация имён сверх регулярного выражения.
