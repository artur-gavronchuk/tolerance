# Срез 6: автопилот

24 сентября 2026. Строится поверх среза 5. Решения приняты автором по поручению владельца.

## 1. Что строим

Владелец задаёт правила, и агент сам берёт подходящие заказы, пока подключён. Утром владелец видит «Пока вас не было»: сколько взято, решено, принято, заработано, почему что-то пропущено. Плюс параллельная работа: агент может вести несколько заказов одновременно.

**Момент продукта:** «Пока вас не было: 5 попыток, 3 решено, 2 принято, $487 выручки, −$21 compute, −$45 комиссия. Чистыми $421. Пропущено 14: 9 ниже минимальной цены, 5 не проходят по доступу.»

Вне среза: мобильные push-уведомления, торг за цену, автоматическая смена версии агента.

## 2. Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Где решение «брать или нет» | На сервере: планировщик в воркере раз в 30 секунд для каждого агента с включённым автопилотом и свежим presence | Правила и данные о заказах на сервере; коннектор остаётся тонким |
| Правила | `enabled`, `skills` (подмножество verified), `min_bounty_cents`, `min_expected_net_cents`, `max_compute_cents_per_job`, `max_concurrent` (1–3), `daily_attempts` (1–20), `currencies` (`USD`, `CRD`), `exclude_keywords` (до 20) | Набор из концепции без лишнего |
| Ожидаемая выгода | `EV = bounty × p_solve × p_pick + 0.15 × bounty × p_solve × (1 − p_pick) − 0.1 × (выплаты) − compute_avg`, где `p_solve` — надёжность агента в направлении (при < 3 попытках — 0.5), `p_pick = 1 / attempts_wanted` для заказов и `3 / slots` для челленджа, `compute_avg` — среднее self-reported compute последних 10 попыток (нет данных — 0) | Прозрачная формула; владелец видит её числа на каждом решении |
| Когда брать | Все правила выполнены, `EV ≥ min_expected_net`, открытых попыток < `max_concurrent`, за сутки < `daily_attempts` | — |
| Остановка | После 3 подряд попыток без «решено» автопилот сам выключается с причиной `losing_streak`; владелец включает вручную | Защита от сломанной версии агента, которая жжёт compute |
| Параллельность | Индекс «одна открытая проверка» заменяется проверкой `count(open) < max_concurrent` под блокировкой агента (для ручного режима лимит 1). Коннектор получает `agent.max_parallel` и ведёт задачи в отдельных горутинах и папках | Без параллельности автопилот ночью берёт одну задачу |
| Журнал решений | Каждое решение планировщика пишется: взято (с EV и числами) или пропущено (с первой непрошедшей причиной); хранится 30 дней | «Почему взял / почему не взял» — главный вопрос доверия к автопилоту |
| Сводка | «Пока вас не было» считается от последнего визита владельца в кабинет (`users.last_seen_app_at`): попытки, решено, принято, выручка, комиссия, compute, чистыми, рейтинг до/после, пропуски по причинам | Цифры из книги и журнала, а не отдельная аналитика |
| Уведомления | Письмо-дайджест раз в сутки, если было движение и включено (`ARENA_SMTP_*`); без SMTP — только в кабинете | Самый дешёвый канал; всё остальное позже |

## 3. Домен

- `autopilot_rules`: `agent_id` (PK), поля правил, `paused_reason`, `updated_at`.
- `autopilot_decisions`: `id`, `agent_id`, `job_id`, `decision` (`took | skipped`), `reason` (`below_min_bounty | below_min_ev | not_eligible | excluded_keyword | concurrency | daily_limit | currency | skill_not_selected`), `ev_cents`, `inputs` (jsonb: p_solve, p_pick, compute_avg), `created_at`. Индекс по `(agent_id, created_at)`; очистка старше 30 дней.
- `users.last_seen_app_at`; `users.digest_email` (bool).
- `proofs`: индекс `proofs_one_open_idx` удаляется, лимит в коде.

## 4. HTTP API

- `GET|PUT /agents/{id}/autopilot`, `POST /agents/{id}/autopilot/resume`.
- `GET /agents/{id}/autopilot/decisions?limit=100`.
- `GET /away-summary` (и отметка `last_seen_app_at` при заходе в кабинет).
- Коннектор: `GET /connector/tasks/next` может вернуть задачу, пока другая в работе (до `max_concurrent`).

## 5. Кабинет

- `/app/a/[agentId]/autopilot`: переключатель, правила, предпросмотр «сейчас взял бы N из M открытых заказов» на текущем рынке, журнал решений с фильтром по причине.
- `/app`: карточка «Пока вас не было» сверху при возвращении.
- `/app/work`: пометка «взят автопилотом», EV на карточке заказа.

## 6. Тесты

- Модульные: EV на таблице кейсов, каждая причина пропуска, выключение после серии проигрышей.
- Интеграционные: планировщик на наборе заказов берёт ровно подходящие и не выше `max_concurrent`; конкурентные тики не берут лишнего; коннектор с `max_parallel = 2` ведёт две задачи; сводка сходится с книгой.
- Приёмка: ночь автопилота на реальном рынке с двумя агентами.

## 7. Порядок

1. Параллельность: снять индекс, лимит в коде, коннектор с горутинами.
2. Правила, EV, планировщик, журнал.
3. Выключение по серии, сводка, дайджест.
4. Кабинет, контракт, e2e, приёмка.
