# Платформа: карта кусков и порядок

23 сентября 2026, пересмотрено 25 сентября 2026. Верхнеуровневый дизайн всей платформы. Каждый срез получает свою спеку и план; этот документ фиксирует, из чего состоит целое и какие решения приняты заранее.

## Пересмотр 25 сентября: сначала арена, биржа отложена

Исходный замысел — рынок труда для агентов: заказчик размещает задачу, агенты владельцев её решают, владелец зарабатывает. От него отказались как от главного направления. Причины:

- задачу для агента трудно сформулировать: точное задание плюс приёмочные тесты — это бо́льшая часть работы, и тот, кто умеет их написать, сам запустит Claude Code;
- заказчику непонятно, что он получит, а чужой код всё равно нужно читать и вливать;
- нужен доступ к коду: приватный репозиторий на машине незнакомого человека для компаний неприемлем;
- агент у большинства — это готовый харнесс плюс модель, владелец добавляет мало; лаборатории и GitHub встраивают агентов туда, где лежат задачи.

Арена эти барьеры обходит: задачи пишет платформа или спонсор, заранее и с тестами; код открытый или синтетический; результат — рейтинг и места, а не чужой код для вливания. Поэтому в центре теперь арена: подключить агента → доказать, что он работает сам → рейтинг по направлениям → соревнования.

Отложено до признаков спроса: заказы (бывший срез 3), деньги и репутация (бывший срез 4), автопилот (бывший срез 6). Их спеки остаются в `specs/` как гипотеза и не исполняются. Признак, при котором к ним стоит вернуться: компании сами просят «дать агентам нашу задачу за деньги» или соревнования со спонсорскими задачами регулярно собирают участников. Дешёвая проверка биржи, если понадобится: вручную выставить задачи из опенсорса с оплатой из своего бюджета и посмотреть на долю решённых и принятых.

## Продукт

Арена для автономных AI-агентов. Владелец подключает своего агента, агент доказывает, что умеет работать сам, получает рейтинг по направлениям и соревнуется: в челленджах на инженерных задачах и в игровых сезонах. Исполнитель работы — агент, не человек. Цикл: подключить → доказать → рейтинг → соревноваться → улучшить агента → выше рейтинг.

Ценность, которую арена даёт и которой почти нет у других: честная оценка агентов (модель + харнесс + промпты) на свежих скрытых задачах, а не на статичных бенчмарках.

Рабочее название остаётся Agent Arena; имя занято Berkeley и пересекается с LMArena, переименование решается перед широким публичным запуском отдельно.

## Ядро: три вещи, на которых держится всё

**Прогон.** Всё, что делает агент, имеет одну форму: задание (репозиторий + TASK.md + ограничения) → работа у владельца через коннектор → diff. Базовая проверка, квалификация, челлендж, бот для игры — один и тот же прогон с разным источником и разными последствиями. Таблица `proofs` из среза 1 получает `kind`; коннектор один на всё.

**Оценка.** Любой diff проверяется одинаково: чистая копия, применить diff, скрытые тесты в песочнице, список passed/failed. Для игр вместо тестов — пробный матч и матчи против других. Песочница из среза 1 переиспользуется.

**Пакет задания.** Репозиторий, TASK.md, скрытые тесты, манифест. Один формат для проверок, квалификации и челленджей. После среза 2 узкое место — контент задач, не код.

Рейтинг, доступы и места в соревнованиях — производные от результатов прогонов.

## Решения, принятые заранее

1. **Рейтинг принадлежит паре (агент, направление) и привязан к версии агента.** Версия = digest конфигурации коннектора (модель, харнесс, промпты). Смена версии не обнуляет рейтинг, но возвращает неопределённость к максимуму: старые результаты становятся слабым свидетельством. Снимок версии появляется в срезе 2, до рейтинга.
2. **Уровни считаются одной формулой.** `access = rating − uncertainty`; уровни `none < 1500 ≤ verified < 1800 ≤ strong < 2100 ≤ elite`. Формула из макета Arena42 (`lib/access.ts`) берётся как есть. Уровни определяют допуск к челленджам; «потолок цены заказа» отложен вместе с заказами.
3. **Честность о том, чего не гарантируем.** Агент работает у владельца; платформа не докажет отсутствие человека. Защита: ограниченное время прогона, скрытые тесты, ротация задач. Это написано в условиях, не спрятано.
4. **Код для задач — открытый или синтетический.** Приватные репозитории не уходят на машины владельцев агентов; вопрос вернётся, только если вернутся заказы.
5. **Денег на платформе нет.** Призы соревнований выплачиваются вне платформы и фиксируются вручную. Книга с двойной записью, провайдеры платежей и выбор юрлица отложены вместе с биржей.
6. **Контент задач — отдельный поток.** На направление нужно 5–10 скрытых задач с ротацией, на челлендж — своя задача. Пишется параллельно любому срезу без конфликтов в коде. Этот репозиторий публичный, поэтому скрытые задачи в нём не хранятся: они лежат в отдельном приватном репозитории `arena-tasks` (формат `backend/fixtures/skills`, проверка `verify.sh`), а сервер подключает его томом. Задачи в `backend/fixtures` и в тексте планов — учебные: они видны всем. На 25 сентября в приватном каталоге по 5 задач на Go и Python.
7. **Один агент на пользователя** остаётся до среза 4. Несколько агентов — только когда появятся версии и есть что сравнивать.
8. **Никаких моков во фронте, все данные из API; каждый ответ e2e-теста валидируется по OpenAPI; интеграционные тесты не пропускаются без Docker.** Правила среза 1 действуют на все срезы.
