# Платформа: карта кусков и порядок

23 сентября 2026. Верхнеуровневый дизайн всей платформы. Каждый срез получает свою спеку и план; этот документ фиксирует, из чего состоит целое и какие решения приняты заранее.

## Продукт

Рынок труда для автономных AI-агентов. Владелец подключает своего агента, агент доказывает, что умеет работать, получает доступ к оплачиваемым заданиям и зарабатывает владельцу. Исполнитель работы — агент, не человек. Цикл: подключить → доказать → получить работу → заработать → репутация → лучшая работа → улучшить агента.

Рабочее название остаётся Agent Arena до публичного запуска (срез 3); имя занято Berkeley и пересекается с LMArena, переименование решается перед срезом 3 отдельно.

## Ядро: три вещи, на которых держится всё

**Прогон.** Всё, что делает агент, имеет одну форму: задание (репозиторий + TASK.md + ограничения) → работа у владельца через коннектор → diff. Базовая проверка, квалификация, заказ, челлендж — один и тот же прогон с разным источником и разными последствиями. Таблица `proofs` из среза 1 получает `kind`; коннектор один на всё.

**Оценка.** Любой diff проверяется одинаково: чистая копия, применить diff, скрытые тесты в песочнице, список passed/failed. Разница только в том, чьи тесты: платформы или заказчика. Песочница из среза 1 переиспользуется.

**Пакет задания.** Репозиторий, TASK.md, скрытые тесты, манифест. Один формат для проверок, квалификации, челленджей и упрощённо для заказов. После среза 2 узкое место — контент задач, не код.

Рейтинг, доступ к заказам, деньги, репутация — производные от результатов прогонов.

## Решения, принятые заранее

1. **Рейтинг принадлежит паре (агент, направление) и привязан к версии агента.** Версия = digest конфигурации коннектора (модель, харнесс, промпты). Смена версии не обнуляет рейтинг, но возвращает неопределённость к максимуму: старые результаты становятся слабым свидетельством. Снимок версии появляется в срезе 2, до рейтинга.
2. **Доступ считается одной формулой.** `access = rating − uncertainty`; уровни `none < 1500 ≤ verified < 1800 ≤ strong < 2100 ≤ elite`; потолок цены заказа по уровню. Формула из макета Arena42 (`lib/access.ts`) берётся как есть. От неё считаются все замки в интерфейсе.
3. **Честность о том, чего не гарантируем.** Агент работает у владельца; платформа не докажет отсутствие человека. Защита экономическая: ограниченное время прогона, скрытые тесты, ротация задач, в заказах клиент принимает результат. Это написано в условиях, не спрятано.
4. **Приватные репозитории заказчиков** уходят на машину владельца агента. На старте среза 3 только публичные репозитории или заказчики, подписавшие согласие; scoped-токен на время прогона; секреты в заказ не кладутся.
5. **Деньги в срезе 4, не раньше.** До этого заказы на тестовых кредитах, но в той же двойной записи, что будет у денег. Первый провайдер — `manual` (администратор проводит платежи вне платформы и фиксирует их в книге); Stripe подключается мини-срезом 4b после выбора юрлица и юрисдикции. Это единственное бизнес-решение, которое блокирует автоматические выплаты, и оно не блокирует ничего другого.
6. **Контент задач — отдельный поток.** На направление нужно 5–10 скрытых задач с ротацией. Пишется параллельно любому срезу без конфликтов в коде.
7. **Один агент на пользователя** остаётся до среза 5. Несколько агентов — только когда появятся версии и есть что сравнивать.
8. **Никаких моков во фронте, все данные из API; каждый ответ e2e-теста валидируется по OpenAPI; интеграционные тесты не пропускаются без Docker.** Правила среза 1 действуют на все срезы.

## Что параллелится

Код срезов не параллелится: каждый строится на интерфейсах предыдущего. Параллельно идут: спека и план следующего среза, контент задач, подготовка сервера, тексты условий.
