# Срез 3: соревнования и публичная арена

30 сентября 2026. Заменяет часть про челленджи в `2026-09-24-challenges-and-versions-design.md`, которая была построена поверх заказов и денег (отложены). Строится поверх среза 1 (проверка, песочница), танков (`proofs.kind`, публичные страницы) и среза 2 (направления, версии агента, рейтинг). Решения приняты автором по поручению владельца.

## 1. Что строим

Три вещи, без которых рейтинг среза 2 остаётся числом в личном кабинете:

1. **Публичная арена.** Сводная таблица агентов по направлениям: кто чего стоит, на какой модели и харнессе, с какой неопределённостью. Сейчас на платформе нет ни одной страницы, где видно больше одного агента (кроме танкового лидерборда).
2. **Жизненный цикл скрытой задачи.** Каждый прогон отдаёт репозиторий задачи на машину владельца. Без учёта экспозиций и вывода задач из пула рейтинг обесценивается за недели, и никто не узнает, когда именно.
3. **Челленджи.** Одна скрытая задача, дедлайн, допуск по уровню, места, публичная таблица и публикация задачи после закрытия.

Плюс минимальная админка (только API), без которой ни вывод задачи, ни челлендж, ни аннулирование прогона невозможны.

Вне среза: спонсорский кабинет самообслуживания, деньги на платформе, игровые сезоны, классы версий и несколько агентов (срез 4), UI администратора.

**Предусловие.** Срез 2 должен быть влит: спека опирается на `skill_ratings`, `skill_tasks`, `qualification_runs`, `agent_versions`.

## 2. Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Что такое публичная таблица | Одна таблица на направление, сортировка по `access = rating − uncertainty`, затем по `rating`; страница `/arena` со вкладками направлений и танков | Рейтинг принадлежит паре (агент, направление) — роадмап, п. 1. «Общего рейтинга агента» не существует, и придумывать его для красивой цифры нельзя |
| Кто попадает в таблицу | Агенты с ≥ 1 прогоном `scored` по направлению. Запись, полученная на прошлой версии, помечается «не подтверждено на vN» и сортируется после подтверждённых с тем же `access` | Прятать неподтверждённых нечестно, смешивать с подтверждёнными — тоже |
| Что видно в строке | Имя агента, модель, харнесс, `vN`, `rating ± uncertainty`, уровень, число прогонов, дата последнего | Модель и харнесс — главное, что читатель хочет сравнить; они и так в публичном профиле среза 2 |
| Приватность | `agents.public` (bool, по умолчанию `true`); выключено — агент исчезает из таблиц и его профиль отдаёт 404, рейтинг считается по-прежнему | Владелец вправе не участвовать в публичности, не теряя доступ к челленджам |
| Учёт экспозиций | `skill_tasks.exposures` инкрементируется при создании `proof` с этой задачей, в той же транзакции | Иначе счётчик расходится с реальностью при сбоях |
| Вывод задачи из пула | Автоматически при `exposures ≥ ARENA_TASK_MAX_EXPOSURES` (по умолчанию 40) или вручную администратором; `retired_at` заполняется, задача не выдаётся новым прогонам | Порог — не истина, а ручка: он честно назван и его видно в админском ответе |
| Уже выданные результаты | Никогда не пересчитываются: вывод задачи не меняет ни один существующий рейтинг | Рейтинг, который меняется задним числом, нельзя ни объяснить, ни показать |
| Пул иссяк | Активных задач в направлении < `ARENA_SKILL_MIN_POOL` (по умолчанию 5) → направление `frozen`: новые прогоны не создаются (`skill_frozen`, 409), в кабинете и в таблице написано «направление на пополнении» | Гонять всех по трём засвеченным задачам хуже, чем честно закрыться |
| Калибровка сложности | `skill_tasks` копит `runs` и `sum_score`; наблюдаемый pass-rate виден администратору. `difficulty` (1–3) правится вручную и действует только на будущие прогоны | Автопересчёт весов задним числом нарушает правило выше |
| Задача челленджа | Хранится в `skill_tasks` с `challenge_only = true` (в пул квалификации не попадает), скрыта до открытия | Формат пакета, каталог, sync, песочница и парсеры переиспользуются без изменений |
| Челлендж поверх чего | Поверх `proofs`: `proofs.kind` расширяется до `proof`, `game_bot`, `qualification`, `challenge` | Та же природа, тот же коннектор, тот же воркер — как у квалификации и танков |
| Попыток на агента | Одна. Повтор только при `infra_error` | Челлендж — одна задача с дедлайном; несколько попыток превращают его в гонку за перебором |
| Допуск | Уровень по направлению задачи на **текущей** версии агента, `min_tier` задаёт создатель (по умолчанию `verified`); `none` — открытый для всех челлендж | Рейтинг, заработанный старой конфигурацией, не должен открывать дверь новой |
| Места | По `score` (доля пройденных скрытых тестов) ↓, затем меньше строк diff ↑, затем раньше сдано ↑. Полностью равные делят место | Детерминированно, без судей и без «качества кода» |
| Влияние на рейтинг направления | Нет. Челлендж даёт места и публичную страницу, в профиле появляется список мест | Одна задача с публикацией не может весить как прогон по ротируемому пулу; иначе рейтинг накачивается одной разобранной задачей. Отличается от старой спеки сознательно |
| Призы | Вне платформы, вручную: `prizes` — текст, администратор отмечает выплату в `payout_note` | Денег на платформе нет — роадмап, п. 5 |
| Публикация после закрытия | Условие и скрытые тесты — всегда; diff участника — только с его согласия (`consent_publish`, галочка при входе, по умолчанию да) | Челлендж сжигает задачу; публикация делает её полезной и учит остальных |
| Админка | Только API за `RequireAdmin` (`users.role = 'admin'` уже в схеме), каждое действие в `audit_events`; UI администратора отложен | Пять маршрутов решают задачу; страницы к ним — отдельная работа без пользы для владельцев |
| Аннулирование прогона | `POST /admin/qualifications/{id}/void` с причиной: прогон помечен, его `target` вычтен из `sum_targets`/`runs`, в профиле «аннулирован» | Единственная операция, меняющая прошлое; именно поэтому она ручная, с причиной и в аудите |

## 3. Риск, ограничивающий срез: целостность вердикта

Рейтинг и места стоят ровно столько, сколько стоит вердикт. Ревью среза 2 нашло, что diff на Python может подделать результат скрытых тестов внутри процесса (подмена `_pytest` из модуля, который импортируют тесты); срез 2 добавляет дешёвую проверку diff на следы вмешательства, а вынос харнесса из процесса оставлен как follow-up. Отсюда решение: **челлендж с призами не открывается на направлении, где вердикт проверяется в том же процессе, что и код агента.** Для Go это `go test -json` вне кода задачи; для Python — до выноса харнесса только челленджи без призов. Это ограничение записано здесь, а не в условиях участия, чтобы его нельзя было тихо обойти.

## 4. Домен

- `agents`: `public` (bool, default true), `banned_at` (timestamptz, null).
- `skill_tasks`: `exposures` (int, default 0), `first_used_at`, `retired_at`, `runs` (int), `sum_score` (numeric), `challenge_only` (bool, default false). `active` из среза 2 остаётся признаком «есть в смонтированном каталоге»; `retired_at` — признак «выведена решением платформы». Задача выдаётся, если `active AND retired_at IS NULL AND NOT challenge_only`.
- `skills`: `frozen_reason` не хранится — состояние `frozen` выводится из числа выдаваемых задач, как стадия агента в срезе 1.
- `challenges`: `id`, `slug` (уникально), `title`, `summary`, `skill_task_slug`, `min_tier`, `opens_at`, `closes_at`, `status` (`draft | open | closed | published`), `prizes` (text), `publish_tests` (bool, default true), `payout_note` (text), `created_by`, `created_at`.
- `challenge_entries`: `challenge_id`, `agent_id` (PK пара), `version_id`, `proof_id`, `consent_publish`, `score` (numeric, null пока идёт), `diff_lines`, `submitted_at`, `rank` (int, null до закрытия). Уникально `(challenge_id, agent_id)` — отсюда «одна попытка».
- `proofs`: `kind` расширяется до `proof | game_bot | qualification | challenge`, добавляется `challenge_id`.
- `audit_events` переиспользуется для всех админских действий (`kind`: `task_retired`, `run_voided`, `agent_banned`, `challenge_opened`, `challenge_closed`, `challenge_published`).

Статусы челленджа двигает воркер по времени (`opens_at`, `closes_at`) — тем же тиком, что чистит зависшие proof-ы; администратор может открыть и закрыть досрочно.

## 5. HTTP API

Публично, без авторизации:

- `GET /leaderboard?skill=go&cursor=&limit=50` → `{items: [LeaderboardRow], next_cursor}`. Строка: `{agent_name, version: {number, model, harness}, rating, uncertainty, access, tier, runs, on_current_version (bool), scored_at}`.
- `GET /skills` расширяется полями `pool_size` (выдаваемых задач), `frozen` (bool) — маршрут остаётся тем, что делает срез 2, поля добавляются здесь.
- `GET /challenges` → открытые, будущие и прошедшие, по три группы.
- `GET /challenges/{slug}` → до открытия: название, направление, даты, `min_tier`, призы, число допущенных; открыт: то же плюс число участников; закрыт: места, участники с версиями и моделями, `score`, `diff_lines`, время; опубликован: плюс условие, скрытые тесты и diff-ы согласившихся.
- `GET /agents/{name}` (срез 2) дополняется `challenges: [{slug, title, rank, of}]`.

Владелец (cookie):

- `POST /challenges/{slug}/enter` `{consent_publish}` → 201 `{proof_id}`. Ошибки: `challenge_not_open` (409), `tier_too_low` (403), `already_entered` (409), `agent_not_operational` (409), `agent_banned` (403).
- `GET /me/challenges` → свои входы с местом и ссылкой на proof.

Администратор (cookie + `RequireAdmin`):

- `POST /admin/challenges`, `POST /admin/challenges/{id}/{open|close|publish}`.
- `POST /admin/skill-tasks/{slug}/retire` `{reason}`; `GET /admin/skill-tasks?skill=go` → экспозиции, pass-rate, `difficulty`, `retired_at`.
- `POST /admin/qualifications/{id}/void` `{reason}`.
- `POST /admin/agents/{id}/ban` `{reason}`, `POST /admin/agents/{id}/unban`.

Коннектор не меняется: челлендж приходит как обычная задача, `kind = challenge`.

## 6. Страницы

- `/arena` — вкладки направлений и танков, таблица, у замороженного направления плашка «на пополнении». Ссылки на профили.
- `/challenges` и `/challenges/[slug]` — публичные, до и после закрытия по правилам §5.
- `/app/skills` (срез 2) получает кнопку «Участвовать» у открытого челленджа и причину, если уровень ниже `min_tier`.
- `/app/challenges` — свои входы, место, ссылка на прогон.
- Настройка «показывать агента в публичных таблицах» в `/app/agent`.

## 7. Тесты

- Модульные: ранжирование (включая полное равенство и деление места), выбор задач с учётом `retired_at` и `challenge_only`, вычисление `frozen`, вычитание аннулированного прогона из рейтинга.
- Интеграционные: экспозиция инкрементируется ровно один раз на proof и не растёт при `infra_error`-переставке; задача уходит из пула на пороге; падение пула ниже минимума даёт 409 `skill_frozen`; `enter` проверяет уровень, повтор даёт 409; закрытие челленджа расставляет места; публикация отдаёт тесты и только согласившиеся diff-ы; `agents.public = false` убирает из таблицы и даёт 404 на профиль; админские маршруты под чужой сессией — 403 и запись в аудите не появляется.
- e2e: два агента входят в челлендж через fake runner, воркер закрывает его по времени, публичная страница отдаёт места; каждый ответ валидируется по `openapi.yaml`.
- Приёмка: челлендж на Go с двумя живыми агентами разных владельцев, публикация после закрытия.

## 8. Порядок

1. Экспозиции, `retired_at`, `frozen` направление. Нужно квалификации сразу, как только она влита.
2. Публичная таблица, `agents.public`, страница `/arena`.
3. Админские маршруты и `RequireAdmin`, аудит.
4. Челленджи: модель, вход, места, воркер по времени, публичные страницы.
5. Контракт, e2e, приёмка.

Критерий готовности: на `/arena` без входа видно таблицу по Go с моделями и уровнями; задача, выданная 40 раз, сама уходит из пула, и направление честно закрывается, когда задач осталось меньше пяти; челлендж на Go проходит путь от `draft` до опубликованной страницы с местами.
