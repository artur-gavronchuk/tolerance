# Бэклог для агента

Очередь работ по Studio после M1. Каждый пункт — один PR: агент берёт верхний незакрытый пункт, читает
`docs/SPEC.md` и `CLAUDE.md`, открывает PR и **не мержит его сам**. Мержит Артур после просмотра.
Пункты собраны по SPEC §5 и по разбору идеи Agent Studio (переписка 18–27 октября 2026).

Как отдавать пункт агенту: «Возьми пункт N из `docs/BACKLOG.md`. Правила из CLAUDE.md в силе. Один PR,
в описании — что сделано, как проверить руками, что отложено».

## Правила очереди

- Один пункт — один PR. Не больше одного PR в работе на пункт, без «заодно поправил дизайн».
- PR готов, когда `pnpm check` зелёный и в описании есть шаги ручной проверки.
- Изменения ядра (`packages/engine`, `packages/git`, `packages/agents`) Артур читает сам перед мержем.
- Решения вне спеки — строкой в `docs/DECISIONS.md`. Итог майлстоуна — в `docs/milestones/`.
- Редизайн, новые темы и экраны вне списка — только по отдельной просьбе.

## Очередь

### 1. Задача → два варианта плана (Planner, SPEC §3.5 п.2) — M3
Из задачи с оценкой агент делает 2 варианта плана в строгой схеме `PlanVariantJson`: подход, плюсы, минусы,
риски, сложность, затронутые компоненты карты, задачи T1… с зависимостями, scope и критериями приёмки.
Валидация сверх zod: уникальные ключи, `dependsOn` только на существующие задачи, граф без циклов, у каждой
задачи есть критерий, `componentId` есть в карте. Ошибки уходят агенту, до 2 повторов. В карточке задачи —
кнопка «Составить план», два варианта рядом, выбор и утверждение варианта.
*Готово, когда:* на любом репо из задачи получается 2 валидных варианта и один можно утвердить.

### 2. Редактор плана перед утверждением — M3
Правка title, description, dependsOn, scope, критериев и агента у задач выбранного варианта; добавить и
удалить задачу; граф задач (DAG, React Flow + dagre). Перед утверждением та же валидация, что в п.1, ошибки
показываются у полей. Утверждённый план не редактируется (только «вернуть в черновик»).

### 3. Worktree и одна задача руками (M2)
`packages/git`: worktree в `~/.studio/worktrees/<project>/<plan>/<task>`, ветки `studio/*`, guard на удаление
(только внутри корня после realpath), коммит за агента, diff от merge-base с untracked. Implement-run: Claude
Code с правом правки только внутри worktree и командами из allowlist проекта, без bypass-permissions.
Monaco diff по задаче. *Готово, когда:* задача «добавь раздел в README» делается в worktree, diff виден,
основная ветка не тронута.

### 4. Исполнение плана и интеграция (M4)
Scheduler: топологический порядок, `maxConcurrency` (по умолчанию 3), задача стартует, когда зависимости
`done` и влиты. Интеграционная ветка, `merge --no-ff` по готовности, детект конфликта (`LC_ALL=C`),
`resolve_conflict`-run, иначе «нужен ручной merge». Вкладка Run: граф задач со статусами вживую, лента событий
по задаче, cancel и retry. Watchdog тишины. После рестарта — `interrupted` и перезапуск.

### 5. Проверка результата против плана (M5) — главное отличие Studio
(a) `testCommand` в интеграционном worktree; (b) scope-check без LLM: файлы diff каждой задачи против её glob;
(c) verify-run только на чтение, по умолчанию другим агентом/моделью, чем исполнитель: вердикт pass / fail /
unclear по каждому критерию со ссылками file:line, плюс незапланированные изменения. Вкладка Verify.
Критерий `check: 'command'` выполняется скриптом, а не оценивается моделью.
*Проверка ценности:* сколько раз красный критерий поймал задачу, которую агент объявил сделанной.

### 6. Ревью и follow-up (M5)
Общий diff плана и по задаче, инлайн-комментарии → markdown → follow-up в новую сессию по задаче →
повторная интеграция и проверка. Кнопка «Создать PR» через `gh` или «показать команды для merge».

### 7. Второй и третий агент (остаток M1)
ACP-адаптер (`@agentclientprotocol/sdk`), Codex и OpenCode, версии в `packages/agents/src/versions.ts`.
Перевести Claude с headless на ACP без изменений движка (события уже нормализованы). Запросы прав в UI.
Чат с агентом в корне проекта и терминал (xterm + node-pty).

### 8. Карта как граф
Граф RepoMap (React Flow + dagre), подсветка компонентов, которые трогает вариант плана (add / modify /
remove). Кэш карты по коммиту: «Обновить» не запускает агента, если HEAD не изменился.

### 9. Полировка для первых пользователей (M6)
Онбординг (какие агенты установлены, как поставить), экран провайдеров OpenCode (GigaChat, YandexGPT,
DeepSeek, Qwen, Ollama) с записью в проектный конфиг, прокси, сборка `.dmg` и `.AppImage`.

## Потом, после первого полного прохода по демо-сценарию

- **Быстрый режим.** Для мелких задач — один вариант плана и сразу исполнение, без шести утверждений подряд.
- **Распространение изменений.** Правка задачи или критерия в утверждённом плане показывает, какие задачи,
  файлы и проверки стали недействительными.
- **Критерии как исполняемые проверки.** Критерий приёмки с `check: 'test'` превращается в тест, который
  агент пишет до реализации; отчёт показывает, какие критерии позеленели.
