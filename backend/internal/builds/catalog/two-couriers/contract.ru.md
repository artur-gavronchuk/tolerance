# Два курьера

Сделай **головоломку про двух курьеров** — статической веб-страницей. Карта — граф: места и дороги между
ними. У двух курьеров, **a** и **b**, у каждого своя цель, и они **ходят одновременно**: за ход каждый
либо идёт по одной дороге, либо стоит. Вся хитрость — не помешать друг другу: двое не могут стоять в
одном месте и не могут разойтись на одной дороге, поменявшись местами.

Мир, герои, вид карты, история — всё твоё (см. конец). Правила и хуки ниже точные; они проверяются.

## Доска

Доска — это обычные данные:

```js
{
  nodes: ['dock', 'bridge', 'tower'],        // id узлов: уникальные строки вида [a-z0-9-]+
  edges: [['dock', 'bridge'], ['tower', 'bridge']],   // дороги между двумя разными узлами
  start: { a: 'dock', b: 'tower' },          // откуда начинают курьеры
  goals: { a: 'tower', b: 'dock' },          // куда каждый должен прийти
}
```

- Рёбра **неориентированные**: `['dock','bridge']` позволяет пройти и из `dock` в `bridge`, и из `bridge`
  в `dock`. Узлы *соседние*, если их соединяет ребро (в любом порядке). Повтор ребра безвреден.
- Ребра из узла в себя нет; «остаться на месте» — это ожидание (`null`), а не ход.
- У курьера **a** своя цель, у **b** своя: если a стоит на цели b, а b — на цели a, это не победа.
- Доски, которые получает страница, связные, узлов не больше 12. Страница должна сама разложить **любой**
  такой граф (способ на твой выбор: круг, силовая раскладка, сетка…); каждый узел виден и кликабелен.

## Тестовый хук: `window.__couriers`

Доступен всегда, а не в особом тестовом режиме. Он управляет той же игрой, что и интерфейс.

```js
window.__couriers = {
  load(board),   // -> true | false
  step(move),    // -> { ok: boolean, reason: string | null }
  reset(),
  getState(),    // -> { positions: {a, b}, goals: {a, b}, turns, won, lastOutcome }
}
```

### `load(board)`

Заменяет игру этой доской: курьеры стоят на `start`, `turns` равно `0`, `won` — `false`, `lastOutcome` —
`null`; страница показывает новую доску (элемент `node-<id>` есть для каждого узла этой доски и нет для узлов
прежней). Возвращает `true`.

Доска **сначала проверяется**. `load` возвращает `false` и **ничего не меняет** (ни состояние, ни страницу),
если: `nodes` — не непустой массив уникальных строк вида `[a-z0-9-]+`; ребро — не пара из двух разных
известных узлов; `start.a` / `start.b` / `goals.a` / `goals.b` — не известный узел; `start.a === start.b`;
`goals.a === goals.b`.

Если оба курьера на старте уже стоят на своих целях, это **не** победа: `won` определяется только после
`step` (см. ниже), но не в `load` и не в `reset`.

### `step(move)`

`move` — это `{ a, b }`. Каждое из `a` и `b` — id узла (идти туда) или `null` (ждать). Отсутствующий ключ
или `undefined` значит `null`. Это **один ход**: оба курьера действуют в нём одновременно.

1. Если игра уже выиграна, верни `{ ok: false, reason: 'FINISHED' }`. Ничего не меняется. (Эта проверка
   идёт первой, даже для хода, который иначе был бы невалидным.)
2. **Проверка.** Ход невалиден, если `move` — не объект, или `a` либо `b` — что-то кроме `null`/отсутствия
   или строки с id узла, **соседнего** с текущим узлом этого курьера. Сюда входят: неизвестный id, не-строка
   (`1`, `false`…), несоседний узел и узел, на котором курьер уже стоит. Невалидный ход **отвергается
   целиком**: верни `{ ok: false, reason: 'INVALID_MOVE' }`; второй курьер тоже не двигается; `turns`,
   позиции, `won` и `lastOutcome` остаются как были.
3. Иначе ход **валиден** и считается: `turns` растёт на 1, вызов возвращает `{ ok: true, reason: null }`.
   Пусть `ta` / `tb` — где каждый курьер хочет оказаться (его цель или его же узел, если он ждёт). Исходы
   проверяются в таком порядке:
   - **collision** — `ta === tb`. Сюда входят и оба в один узел, и один курьер в узел другого, который
     **ждёт**. **Оба** остаются там, где были.
   - **swap** — `a` идёт в текущий узел `b`, а `b` идёт в текущий узел `a`. **Оба** остаются.
   - **moved** — всё остальное: оба идут к своим целям. Занять узел, который другой курьер **покидает в этом
     же ходу**, можно (курьер a идёт туда, где стоял b, пока b идёт дальше в другой узел). Оба ждут — тоже
     валидный ход `moved`.

   Collision и swap — валидные ходы (`ok: true`, `reason: null`, `turns + 1`): о них говорит только
   `lastOutcome`.
4. `lastOutcome` становится строкой `'moved'`, `'collision'` или `'swap'`. После `load` / `reset` он `null`,
   а при отвергнутом ходе сохраняет прежнее значение.
5. **Победа**: после валидного хода `won` становится `true`, если курьер a стоит на `goals.a` **и** курьер b
   стоит на `goals.b` в один и тот же момент. Стоял на цели раньше, потом ушёл — не считается. После победы
   любой `step` возвращает `FINISHED` и ничего не меняет.

### `reset()`

Возврат к началу **текущей загруженной** доски (из последнего успешного `load` либо уровня, который показывает
страница): позиции = `start`, `turns` 0, `won` false, `lastOutcome` `null`, а незавершённый ход в интерфейсе
сбрасывается (см. ниже).

### `getState()`

```js
{ positions: { a: 'dock', b: 'tower' }, goals: { a: 'tower', b: 'dock' },
  turns: 0, won: false, lastOutcome: null }
```

`positions` и `goals` — id узлов. Возвращается **снимок**: изменение возвращённого объекта не должно влиять на игру.

## Страница

При свежей загрузке страницы (никто ещё не вызывал `load`) показан твой собственный уровень — **уровень 1**.
Сделай **не меньше 3 уровней**, каждый решаем по этим точным правилам (ожидание, следование и уклонение — как раз
то, что делает их интересными; уровень, который нельзя пройти, — это баг), и способ переходить между ними
(выбор уровня, «дальше/назад», что угодно). Уровень — это просто доска; переключение уровня ведёт себя как
`load(board)`.

| `data-testid` | Что это |
|---------------|---------|
| `board` | контейнер карты (виден) |
| `node-<id>` | по элементу на каждый узел загруженной доски, например `node-dock`; виден, кликабелен. Других test id, начинающихся с `node-`, быть не должно |
| `agent-a`, `agent-b` | два курьера, видны; атрибут `data-node="<id>"` хранит узел, на котором курьер стоит **сейчас** (он меняется в момент смены состояния, а не после анимации) |
| `select-a`, `select-b` | кнопки выбора курьера, которым ты управляешь; у выбранной `aria-pressed="true"`, у другой `"false"` |
| `step` | кнопка: совершает отложенный ход |
| `turn-count` | число ходов: в тексте элемента ровно одно число — значение `turns` (то есть никаких «уровень 2» внутри) |
| `reset` | кнопка: то же, что `reset()` |

Как ходить мышью (это тоже проверяется):

- Ты всегда управляешь одним курьером: сначала **a** (после загрузки страницы, `load`, `reset`). `select-a` /
  `select-b` переключают; больше ничто выбор не меняет.
- Клик по `node-<id>` делает `<id>` **отложенной целью** курьера, которым ты управляешь, заменяя его прежнюю
  отложенную цель. Он не делает ход и ничего не проверяет. Клик должен работать и по узлу, на котором стоит
  курьер: фишки курьеров не должны перехватывать клики, предназначенные узлу.
- Кнопка `step` вызывает `step({ a: pendingA ?? null, b: pendingB ?? null })` — ровно тот же вызов API — и
  затем очищает обе отложенные цели, был ход валидным или нет. После победы она больше ничего не делает
  (`step` возвращает `FINISHED`).
- `load`, `reset` и смена уровня очищают отложенные цели и возвращают управление курьеру **a**.
- Покажи отложенные ходы, отвергнутый ход, столкновение и обмен так, чтобы игрок понял (стрелки, тряска,
  сообщение — на твой вкус). Это не проверяется, но за это голосуют люди.

## Твоё — придумать

Мир и герои: курьеры, дроны, паромы, мыши с посылками, призраки в особняке, поезда. Вид карты, анимация хода,
стук столкновения, «нет, так нельзя» при обмене. Звук с кнопкой выключения, история уровня, подсказки, своя
отмена хода (в API её нет), рекорд ходов на уровень, галерея уровней. Чем приятнее планировать танец двух
фигур, тем больше голосов.
