# Зеркальная мастерская

Сделайте **рисовалку, где каждый штрих превращается в симметричное существо, эмблему или узор**. Человек
проводит одну линию, а мастерская повторяет её по холсту по правилам зеркала и поворота: бабочка из одного
крыла, снежинка из каракули, мандала из одного взмаха руки. Все, кто заходит в галерею, рисуют в вашей
мастерской и голосуют за ту, что понравилась больше, поэтому ощущения важны не меньше правил: штрих,
который течёт за курсором, цвета, которыми хочется рисовать, холст, похожий на место, где что-то
создают, и свой собственный вид.

## Правила (точные — они проверяются)

### Поле и копии

- Поле рисования — квадрат, **0 … 256 по обеим осям**, `x` вправо, `y` вниз, **целые координаты**. Точка —
  массив `[x, y]`.
- Два преобразования поля (центр поля — `(128, 128)`):
  - **M**, зеркало: `M(x, y) = (256 − x, y)`
  - **R**, поворот на четверть оборота: `R(x, y) = (256 − y, x)`
- Штрих — список точек. Его **копии** — тот же список, пропущенный через преобразования поточечно, в том же
  порядке. Восемь возможных копий, именно в таком порядке:

  | # | копия | формула |
  |---|-------|---------|
  | 0 | оригинал | `p` |
  | 1 | R | `R(p)` |
  | 2 | R² | `R(R(p))` |
  | 3 | R³ | `R(R(R(p)))` |
  | 4 | M | `M(p)` |
  | 5 | R∘M | `R(M(p))` (сначала зеркало, потом поворот) |
  | 6 | R²∘M | `R(R(M(p)))` |
  | 7 | R³∘M | `R(R(R(M(p))))` |

- **Режим** решает, какие из этих копий есть у штриха (берутся в порядке таблицы):

  | режим | копии | сколько |
  |-------|-------|---------|
  | `single` | 0 | 1 |
  | `mirror` | 0, 4 | 2 |
  | `turn4` | 0, 1, 2, 3 | 4 |
  | `kaleido8` | 0 … 7 | 8 |

  Копии **никогда не склеиваются и не отбрасываются**, даже когда совпадают (точка на оси симметрии —
  собственное зеркальное отражение, но копия всё равно есть).
- Все копии рисуются на холсте, а холст всегда соответствует `getState()`.

### Штрихи

- Штрих **помнит режим, цвет и толщину на момент создания**. Смена режима (цвета, толщины) позже никогда
  не меняет уже существующие штрихи: их копии остаются ровно такими, какими были.
- Штрихи хранятся в порядке рисования.
- Входные точки при создании штриха **нормализуются**: каждая координата округляется до ближайшего целого
  (`Math.round`), затем ограничивается диапазоном `0 … 256`. Копии считаются от нормализованных точек.
  В штрихе может быть всего одна точка (точка-пятнышко).
- Вызов, из которого нельзя сделать штрих (`points` — не массив, пуст или содержит точку, которая не пара
  конечных чисел), **игнорируется**: штриха нет, записи в истории нет, исключение не бросается.

### История

- Каждый добавленный штрих (мышью или через API) — **одно отменяемое действие**; один протяг мыши — один
  штрих.
- **undo** откатывает последнее действие из ещё применённых, **redo** применяет последнее откатанное
  действие снова. Если откатывать или применять нечего, оба ничего не делают.
- Новый штрих после undo **сбрасывает историю redo** (`canRedo` становится `false`).
- **clear** убирает все штрихи и является **одним отменяемым действием**: один undo возвращает все штрихи
  в прежнем порядке, с прежними режимами и копиями. Как и любое новое действие, очистка обнуляет историю
  redo. Очистка **пустого холста — не действие**: ничего не меняется, ничего не становится отменяемым,
  история redo остаётся как была.
- Смена режима — **не** действие: её нельзя отменить, и она не трогает историю redo. Undo и redo никогда не
  меняют текущий режим.

### Хук

Страница выставляет `window.__mirror` (синхронно, сразу после загрузки страницы):

```js
window.__mirror = {
  setMode(mode) {},                    // 'single' | 'mirror' | 'turn4' | 'kaleido8'; всё остальное игнорируется
  addStroke({ points, color, width }) {}, // points: [[x, y], ...]; ТЕКУЩИЙ режим; одно отменяемое действие
  undo() {},
  redo() {},
  clear() {},
  getState() {},   // см. ниже
}
```

```js
getState() → {
  mode: 'turn4',                    // текущий режим
  strokes: [                        // в порядке рисования
    {
      points: [[10, 20], [30, 40]], // нормализованные точки, массивы [x, y]
      color: '#ff3366',             // ровно как передали (строка)
      width: 4,                     // ровно как передали (число)
      mode: 'mirror',               // режим в момент создания штриха
      copies: [                     // по массиву точек на копию, в порядке таблицы выше
        [[10, 20], [30, 40]],       // копия 0 — всегда исходные точки
        [[246, 20], [226, 40]]      // ...затем остальные копии режима этого штриха
      ]
    }
  ],
  canUndo: true,
  canRedo: false
}
```

`getState()` возвращает снимок (обычные массивы и объекты; его изменение не должно менять мастерскую).
Хук и экран всегда согласованы: всё нарисованное есть в `getState()` и наоборот. Дополнительные поля
допустимы. `setMode`, `undo`, `redo`, `clear` и `addStroke` действуют сразу: состояние, прочитанное сразу
после вызова, уже включает их.

### Рисование мышью

- Нажать кнопку внутри элемента **`drawing`**, подвигать, отпустить — это один штрих. Он попадает в
  состояние при отпускании кнопки (штрих в процессе можно показывать вживую) и использует текущие режим,
  цвет и толщину собственных контролов мастерской. Его точки нормализуются так же, как любые другие.
- Рамка элемента отображается на поле **линейно по обеим осям**: левый край — `x = 0`, правый — `x = 256`,
  верхний — `y = 0`, нижний — `y = 256`. Протяг от 25 % до 75 % ширины рамки приходится примерно на
  `x = 64 … 192`. Сделайте элемент квадратным, чтобы картинка не растягивалась, и не ставьте на него
  border или padding, сдвигающие содержимое относительно рамки.
- Должны работать и pointer-события, и мышиные (используйте pointer events и `setPointerCapture`; добавьте
  `touch-action: none`, чтобы можно было рисовать пальцем).
- В окне 1024 × 768 элемент `drawing` виден целиком без прокрутки, и ничто его не перекрывает.

### Элементы (`data-testid`)

| `data-testid` | Что это |
|---------------|---------|
| `drawing` | canvas (или SVG), который принимает ввод указателя, см. выше |
| `mode` | **`<select>`**, значения опций ровно `single`, `mirror`, `turn4`, `kaleido8` (подписи ваши). Его значение всегда равно текущему режиму: выбор опции задаёт режим, а `setMode` обновляет select |
| `undo` | `<button>`; он `disabled` ровно тогда, когда `canUndo` равно `false` |
| `redo` | `<button>`; он `disabled` ровно тогда, когда `canRedo` равно `false` |
| `clear` | `<button>`, делающая то же, что `clear()` |

## Тестовый режим

С **`?test=1`** в URL холст стартует **пустым** (`strokes: []`, `canUndo` и `canRedo` равны `false`), и ничто
не рисует само: никакой анимации, меняющей состояние, никаких демо-штрихов, ничего, восстановленного из
`localStorage`. Без `?test=1` можно встречать людей стартовым рисунком, демо или сохранённой сессией.
Начальный режим — на ваше усмотрение (любой из четырёх).

## Что придумать самим

Всё, что видят люди: тему (стеклянно-неоновое ателье, мастерская резной бумаги, морозное окно, витраж,
ночной сад, машина эмблем для звездолёта…), палитру и управление толщиной, как называются и иллюстрируются
режимы, направляющие симметрии, фон, отрисовку штриха (свечение, кисть, градиент, искры), стартовый
рисунок, сохранение в PNG, горячие клавиши, звук. Контракт фиксирует, чем *являются* копии; как они
выглядят — вся суть работы. Уважайте `prefers-reduced-motion` и сделайте так, чтобы пользоваться можно было
и с телефона.
